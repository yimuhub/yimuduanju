# M5 对话直剪 · 实施与验收记录（2026-11-16）

分支 `feature/studio-pro-edit-v1`｜提交 `f426084`（M5）、`7258f77`（导出选项与单测）

## 一、为什么之前"说一句就能剪"做不到

不是前端画不出来，也不是模型不会理解，而是缺四层可执行的基础设施：

| 缺的东西 | 具体表现 | 本次补法 |
|---|---|---|
| 工具协议 | 模型只能返回文字，网关请求体只有 messages/temperature，没有 tools/tool_calls | 定义 `yimu-timeline` 结构化动作协议，把 EDL 清单（含 clientKey）注入 systemPrompt |
| 执行运行时 | 没有事务、没有幂等、没有审计，改一半失败就留下半截状态 | `POST /timeline/agent-ops`：版本校验 + 整批原子 + 幂等键 + `agent_edit_ops` 审计 |
| 稳定引用 | 自动保存会 delete+insert 重建片段 id，0.4s 后选中/字幕/Agent 定位全失效 | `timeline_clips.client_key`（0029 回填并建唯一索引），前后端一律用 clientKey 定位 |
| 验证闭环 | 模型输出不可信，直接落库等于把生产数据交给概率 | 前端先本地同款纯函数 dry-run 出 diff，人点"应用"才走服务端事务 |

## 二、落地清单

### 服务端
- `shared/timeline-ops.ts`：纯函数动作引擎，op = move / trim / split / delete / subtitle / speed / volume / lock / track；引用支持 `clientKey` / `id` / 镜头码 `V1#3`；同轨同时刻冲突自动找空轨（显式指定被占则整批报错）；锁定片段拒改；单批 40 条、轨道上限 20 条；**任一条失败整批拒绝并原样返回文档**。
- `describeTimelineForAgent()`：输出「版本 + 轨道 + `key=… | V1#1 | shot=… | 起止s | 文本 | 锁定`」，模型据此选片段，不必猜 id。
- `timeline.service.applyAgentOps()`：幂等查审计 → 版本校验（不符 409）→ 纯函数 dry-run（失败 400 列错误）→ `saveDocument` 回传 clientKey → 写审计。
- `0029_timeline_client_key.sql`（回填 + `(project_id, client_key)` 唯一索引）、`0030_agent_edit_ops.sql`（base/result version、ops/diffs、status、幂等键唯一索引）。
- 导出新增 `videoLaneMode`：`sequence` 保持旧行为，`main` 只取主链（排除 alt/overlay/exportEnabled=false）。

### 客户端
- `useEdlEditor(data)`：新片段同时生成 id + clientKey；保存后按 clientKey 重映射选中态；`applyAgentOps()`（本地 dry-run → 刷 pending → 服务端应用 → 入撤销栈含轨道前后快照）、`previewAgentOps()`。
- `EdlContext`：编辑器实例共享给时间线与对话，消除 `useEdlEditor ↔ StudioShell` 循环依赖。
- `TimelineOpsCard`：解析围栏 → 展示逐条 diff / 错误 / 时长变化 → 「应用」调服务端；409 提示重新生成；已应用状态持久化到 localStorage。
- 对话文本流剥离动作围栏，避免用户看到 JSON。
- 导出面板新增「画面：只导主链 / 全部串行」下拉。

## 三、交互流程

1. 用户说「把第二镜剪短 0.5 秒，字幕改成……」
2. 模型读注入的 EDL 清单，回一段自然语言 + 一个 `yimu-timeline` 代码块（带 baseVersion / summary / ops）。
3. 卡片本地干跑：能改的列 diff，不能改的（锁定/被占轨/引用不存在）直接列错误，应用按钮禁用。
4. 用户点「应用」→ 服务端事务落库 → 时间线即时刷新、可 Ctrl+Z 撤销。
5. 若期间别人（或自己）改过时间线导致版本变化 → 409，提示让 Agent 重新生成，不会覆盖。

## 四、边界与异常

- 引用过期 / 编造 clientKey：服务端解析失败整批 400，不会误删别的片段。
- 同轨时间冲突：未指定目标轨时自动落到空轨；显式指定且被占则拒绝，提示换轨。
- 锁定片段：任何改动被拒（与面板锁语义一致）。
- 网络重试：幂等键命中直接回放上次结果，不重复改。
- 本地有未保存修改：应用前强制 flush，失败则中止并提示。
- 多画面轨导出：默认只导主链，避免把备选镜头串进成片；需要旧行为可切「全部串行」。

## 七、追加落地（第二轮，按"所有提到功能全部落地"）

### 7.1 大文件上传（原 25MB 硬限）
- 服务端：`POST /uploads/chunks`（init）→ `PUT /uploads/chunks/:id/part?index=n`（按序追加，单片 12MB）→ `POST /uploads/chunks/:id/complete`（校验声明/实收/落盘三方字节数后登记资产）。总上限 2GB。
- 客户端：`uploadLocalFile` 超过 25MB 自动切片，逐片上报进度；≤25MB 仍走单请求（不多一次往返）。
- 实测：init → part(1024B) → complete 全链路 200，资产正常登记；测试数据已删除。

### 7.2 多画面轨真正叠加合成（画中画）
- `videoLaneMode` 新增 `overlay`：主链铺底，V2/V3 按各自 `timelineStart` 叠为画中画（42% 等比缩放、右下角 32px 边距、`eof_action=pass`、`enable=between(t,start,end)`）。
- 仍有 `main`（只导主链）与 `sequence`（旧串行）两档，导出面板三选一，默认 `overlay`。
- ffmpeg 配方已独立验证：4s 红底 + 2s 蓝块，t=2s 叠加区域像素为蓝色、t=0.5/3.5s 为红色；输出时长严格 4.000s。

### 7.3 Agent 剪辑历史（审计回放）
- `GET /timeline/agent-ops?limit=n` 返回最近记录（版本区间、summary、逐条 diff）。
- 时间线工具条新增「历史」按钮：弹层列出每次剪辑的 vN→vN+1、改动条数与 before→after，可回溯"哪次对话改了什么"。
- 实测：接口返回 200（空列表正常）。

### 7.4 资产包素材（第三类来源，真正可用）
- 定义 `.yimupack / JSON` 清单格式：`{"format":"yimu-pack","name":…,"items":[{name,url,kind,durationSeconds}]}`。
- 导入时逐条校验：URL 仅允许 `http(s)` / `/uploads/`，类型仅 video/image/audio，最多 200 条；一条不合法整包拒绝。
- 支持逐条插入或"全部插入时间线"。zip 仍建议解压后本地多选（浏览器不做解压是安全边界，不是能力缺失）。

### 7.5 字幕"点击进入 / 双击编辑"
- 单击字幕片段（位移 <4px 判定为点击）直接进入就地编辑；拖动不会误触发。
- 双击仍进入编辑，输入框内可继续双击选词；IME 组合态 Enter 不当提交（原有逻辑保留）。

### 7.6 桌面宠物（屏幕级悬浮）
- 浮窗头部新增「投到桌面」：Chromium 116+ 用 Document Picture-in-Picture 生成**系统级置顶小窗**，可拖到屏幕任意位置；点小球聚焦主窗口并展开对话。
- Safari / Firefox 无该 API，自动回退页内可拖拽小球并提示原因。全平台透明置顶（穿透桌面）仍需 Tauri 壳，属原生客户端范畴。

### 7.7 模型协议健壮性
- 解析器新增"裸 JSON 兜底"：模型漏写 ```yimu-timeline 围栏时，用括号配平扫描提取完整对象；仍保持"任一 op 非法 → 整块拒绝"。
- 协议里补了一条完整示例（trim + subtitle），降低小模型改字段名的概率。
- 解析器单测从 6 例增至 8 例（裸 JSON 正例 / 非法 op 反例）。

### 7.9 仍然存在的边界（不粉饰）
1. 画中画位置/大小目前是固定默认（右下 42%），还没有"拖动定位/缩放"的可视化控件；数据层没有 transform 字段，做这个要再加一轮。
2. 桌面宠物的"透明背景 + 点击穿透"只有 Tauri 原生窗口能做到；Document PiP 是置顶小窗，不是透明贴桌面。
3. 真实模型对协议的遵循率仍未用真实 Key 批量实测（当前只有 mock/结构校验与兜底）。
4. zip 资产包未在浏览器内解压（无 zip 依赖，且解压大包会吃内存）；走 .yimupack 或本地多选。
