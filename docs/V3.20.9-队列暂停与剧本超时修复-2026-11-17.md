# V3.20.9 队列暂停与剧本超时修复

## 问题
1. 用户在队列页暂停任务后，`releaseToPending` / `releaseTransient` 仍无条件把任务写回 `pending`，暂停被在途释放逻辑复活。
2. 本机残留 6 个 `nest --watch` 实例，多个 BullMQ 消费器同时抢任务，DB 与 Redis 状态不一致。
3. DB 中任务 `queued`、Redis 无对应 BullMQ 消息时形成“假排队”，任务永远 0%。
4. 剧本技能调用文本模型没有任务级超时，上游不返回时任务永久 `running 0%`。

## 修复
- `releaseToPending` / `releaseTransient` 的 UPDATE 增加 `status NOT IN ('paused','cancelled','succeeded','failed')`，返回空则跳过。
- 新增 `YIMU_QUEUE_MODE=inline` 显式开关，强制进程内串行消费，用于本机调试或 Redis 脏队列。
- `STALE_QUEUED_MS` 由 5 分钟降为 60 秒；队列模式回收前核对 BullMQ 真实 waiting/active。
- 文本请求 `AbortSignal.timeout(90_000)`；剧本任务外层 `Promise.race` 150 秒兜底，超时给出可读错误。
