# 一幕 YIMU：本地优先、官方模型服务与质量优先实施蓝图

> 决策日期：2026-10-31
> 对应版本：v3.4.1 之后的架构方向
> 本文是产品与技术决策的实施基线，不替代 `代码审查报告-2026-10-31.md` 中的缺陷清单。

## 1. 决策定稿

### 1.1 产品形态

一幕定位为：**本地优先、源码可见、可自由自部署的 AI 短剧生产工具；官方模型服务是可选的商业化云端能力。**

三个边界必须同时成立：

1. 不配置任何云端账号，也能在本地完成项目、剧本、分镜、画布、素材管理和剪辑编排。
2. 用户自带模型 Key（BYO Key）时，软件不额外收取生成费用，也不强制连接官方服务。
3. 使用官方模型服务时，只要求用户配置官方访问令牌；上游模型厂商密钥永不进入用户机器。

因此，不做本地强制登录、不做全局多租户、不把云端账号体系强加给纯离线用户。原审查报告中「补全站用户系统」的建议改为：**本地默认单一工作区；只有使用官方模型服务时才建立云端账户关系。**

### 1.2 许可证与“开源”口径

现有 `LICENSE` 已采用 BUSL-1.1，Additional Use Grant 已包含「连续 12 个月直接商业价值低于人民币 10 万元免费，达到或超过需商业授权」，与当前商业决策一致，无需重写主体条款。

但必须统一对外措辞：

- 可以说：**源码开放、源码可见、可审计、可修改、可自部署、商业授权制**。
- 不应直接说：**OSI 开源、MIT/Apache 式自由开源**。BUSL-1.1 自己明确声明不是 Open Source license。
- 「10 万以内免费 + 以上授权」与 OSI 定义下的无条件商业使用权不能同时承诺。若未来改用 Apache-2.0/MIT，就必须放弃这个授权门槛，商业化只依靠官方模型服务、云同步和企业服务。

推荐保留现有 BUSL 路线。商业授权依靠许可证、合同、登记与企业服务履约，**不依靠本地授权锁**。本地代码可被修改，任何本地强制校验都可被绕过，还会误伤正常离线用户。

### 1.3 商业化拆成两条互不强绑的线

| 收入线 | 收费对象 | 履约位置 | 与本地软件的关系 |
|---|---|---|---|
| 官方模型 token / 生成用量 | 使用官方模型服务的人 | 官方云端 | 可选；不用也能自部署和 BYO |
| 商业授权 / 企业授权 | 超过免费层或需要白标、闭源分发的人 | 许可证与合同 | 不通过本地 DRM 强制 |

不做以下事情：

- 不把上游厂商密钥编译进桌面端或本地服务。
- 不用本地 `projects.total_cost` 作为官方扣费依据；用户可修改本地数据库。
- 不因为用户未登录、未联网或未购买授权而禁用本地核心功能。
- 不把「软件授权额度」和「模型 token 余额」混成一个概念。

## 2. 官方模型服务架构

### 2.1 三个平面

```text
本地执行平面（用户机器）
  项目 / 剧本 / 分镜 / 画布 / 任务队列 / 素材 / 导出
  Provider: official | byo | mock
             |
             | 仅 official 通道，携带用户官方访问令牌
             v
官方模型服务平面（你的云端）
  令牌认证 / 云端账户 / 余额与额度 / 限流 / 审核
  模型路由 / 质量策略 / 上游密钥 / 真实 usage 与账单
             |
             v
上游模型厂商
  文本 / 图片 / 视频 / 音频模型

商业授权平面
  BUSL / 商业授权登记 / 企业合同 / 商标与白标授权
```

### 2.2 本地 Provider 的三种费用语义

本地任务必须区分费用来源，不能继续只写一个 `cost`：

| 通道 | 费用语义 | 权威来源 |
|---|---|---|
| `official` | 官方实际扣费，云端返回用量与金额 | 官方云端账单 |
| `byo` | 用户向上游自行付费；本地金额只是估算 | 本地估算，明确标注 |
| `mock` | 演示通道，永远为 0 | 本地固定为 0 |

建议任务输出增加以下结构，而不是继续扩充零散字段：

```ts
billing: {
  source: 'official' | 'byo_estimate' | 'free',
  currency: 'CNY',
  estimatedCost?: number,
  chargedCost?: number,
  cloudUsageId?: string,
  mock?: boolean,
}
```

官方云端负责认证、配额、限流、预授权、结算、退款与对账；本地只保存云端返回结果的只读镜像。本地预算上限仍有价值，但语义是「用户给自己设置的刹车」，不是官方配额，也不能阻止恶意客户端绕过。

### 2.3 官方模型的竞争力不只是转售 token

官方通道应逐步提供本地 BYO 难以复用的生产能力：

- 按短剧环节选择模型：剧本、首帧、视频、配音分别路由，而不是一个模型打全链路。
- 针对角色一致性、漫剧风格、镜头时长的提示词与参数模板。
- 失败分类与智能重试：内容拒绝、限流、超时、供应商故障采用不同策略。
- 可观测的真实用量、失败率和单镜头成本。
- 后期可增加云端排队加速、跨设备同步和团队协作，但均作为增值能力，不影响离线核心功能。

## 3. 质量优先的异步生产链

### 3.1 修改产品承诺

放弃「90 秒全自动出片」作为主卖点，统一为：

> 异步生成，可排队、可离开、可恢复；关键镜头可反复打磨，确认后再进入下一阶段。

「快速预演」可以保留为低质量、低成本草稿模式，但不能与最终成片共用同一质量承诺。

### 3.2 从优先级排序升级为真正的任务依赖

当前 `storyboard.service.ts` 用图片 priority 75、视频 priority 65 表达「先图后片」，但 Redis 队列认领只按 `createdAt`，顺序并不可靠。priority 不能替代依赖关系。

目标任务模型：

```text
剧本解析
  -> 角色/场景设定生成
  -> 分镜生成
  -> 镜头首帧生成
  -> 首帧人工确认（可自动跳过，但默认质量模式开启）
  -> 镜头视频生成（dependsOn: 首帧任务）
  -> 配音/音效
  -> 合成与质检
  -> 导出
```

最低实现要求：

1. `generation_jobs` 增加依赖信息，或建立 `job_dependencies(job_id, depends_on_job_id)`。
2. 调度器只认领「依赖全部成功」的任务，不再用优先级猜顺序。
3. 首帧失败时，视频任务标记为 `blocked`，不裸跑、不扣视频费用。
4. 重试首帧后，被阻断的视频可一键恢复；重试视频不必重跑首帧。
5. 任务支持取消、暂停项目、单镜重试、失败重试和优先级调整。
6. 所有上游请求有超时；限流采用有上限的退避，不允许永久 pending。
7. 页面刷新或服务重启后任务可恢复；离开页面不影响队列。

### 3.3 质量闭环优先级

按对成片质量的影响排序：

1. **角色与场景设定闭环**：快速创建也必须抽取并持久化角色，否则下游角色一致性没有输入。
2. **首帧质量门**：首帧未确认时，质量模式不自动进入视频；预演模式可自动通过。
3. **镜头版本管理**：每次重生成都保留版本，可对比、回滚、选定，不覆盖已选中的产物。
4. **跨镜一致性**：角色参考图、场景参考图、上一镜尾帧等输入必须可追踪，知道每条视频用了哪些参考。
5. **真实质检拆分**：完整性检查、技术检查（分辨率/时长/音轨）、内容质量检查分别呈现；不能再把缺图比例命名为「角色一致性」。
6. **批量操作只作用于选择集**：多选镜头、批量改参数、只重跑失败、操作前显示范围与估算成本。

## 4. 画布：可渐进发现的核心工作台

### 4.1 定位

画布不是新人必须学会的第一步，也不是与项目脱节的彩蛋，而是：**同一个项目的可视化工作面。**

- 对新手：默认从流程总控进入，系统已自动铺好「剧本 -> 角色/场景 -> 分镜 -> 成片」节点，无需理解节点编辑器。
- 对进阶用户：可以从任何角色、场景、镜头、资产进入画布对应节点，进行参考连接、版本比较、局部重生成与导演台操作。
- 对产品：不主动把画布作为宣传第一站，但在项目导航中保持一级入口，并让所有实体都有「在画布中打开」。

流程总控回答「下一步做什么」；画布回答「整个项目如何关联、我要精修哪一部分」。两者不是竞争入口。

### 4.2 单一数据源

当前画布把业务字段和布局一起存进 localStorage，容易与分镜、导演台、时间线产生多份真相。目标拆成两层：

**业务实体仍由现有数据库表持有：**

- `shots`：时长、提示词、景别、首帧、视频、配音等业务字段。
- `characters` / `scenes` / `assets`：设定与产物。
- 画布业务节点只保存 `entityType + entityId + layout`，不保存会过期的业务副本。

**画布文档只保存画布自有信息：**

建议新增 `canvas_documents`：

```text
id              uuid
project_id      uuid
episode         integer
document        jsonb   -- 自由节点、文本/便签、连线、viewport、布局、节点参数
revision        integer -- 乐观锁，防多窗口覆盖
created_at      timestamp
updated_at      timestamp
unique(project_id, episode)
```

自由生成节点若没有对应业务实体，可以属于 `canvas_documents.document`；一旦回写为首帧、视频或项目资产，就以资产/镜头 ID 建立引用。

### 4.3 存储与性能底线

- localStorage 不再作为画布数据库；迁移期只用于读取旧存档。
- 服务端保存是主存储；IndexedDB 可作为离线草稿和恢复缓存。
- 图片、视频不以 base64 写进画布 JSON，统一落资产文件并保存 URL/资产 ID。
- 保存失败必须可见，不能 `catch {}`；采用防抖保存、revision 冲突提示和未保存状态徽标。
- 创建、删除、连线、拖拽结束统一进入撤销栈。
- 上游引用使用邻接索引，避免每个节点渲染都全图 BFS。
- 大画布按需渲染节点详情、缩略图和 3D 导演台；three.js 不应随首屏加载。

### 4.4 画布实施顺序

1. 先修正确性：节点写入错误、保存静默失败、参数不记忆、业务字段不同步。
2. 再做 `canvas_documents` 与旧 localStorage 迁移，保证刷新、重启、换浏览器可恢复。
3. 统一实体引用与深链，去掉 `gen.duration` 等重复业务副本。
4. 补撤销、多选、批量、版本对比与性能优化。
5. 最后才扩展更多节点类型和视觉效果；不在数据孤岛未解决前继续堆功能。

## 5. 分期路线

### 第一阶段：正确性与安全底线

- 修资产任意文件读取、结算幂等、mock 零计费、上游请求超时。
  - 已完成：资产读取限制在上传目录内；mock 产物零计费并在任务/资产/分镜/导出四处标注「演示」。
  - 已完成：结算改为「状态 CAS + 单事务」，成功置态与项目费用累加同生共死；重复/并发结算只有一个生效。
    失败结算与重试同样用 CAS，不会把已成功的任务改回 failed/pending。
    历史脏数据用 `node scripts/recalc-cost.js`（默认只读对账，`--apply` 写回）以「成功任务金额合计」为准重算。
  - 未完成：上游请求超时与退避。
- 修首屏开拍断链、3D 截图覆盖节点、画布保存无提示。
  - 已完成：三处交互缺陷均已修复；画布保存失败会明确提示。
- 本地部署明确默认仅本机访问；局域网开放由用户显式开启，不伪造多用户安全边界。
  - 已完成：网关默认只监听回环，非回环监听需显式 `YIMU_ALLOW_LAN=true` 否则拒绝启动；
    客户端自带的身份头一律剥掉（原先可伪造 `x-larkgw-suda-webuser` 冒充任意用户）；
    Docker 端口改为只发布到宿主 127.0.0.1，企业版 compose 用 `SERVER_BIND_HOST` 显式放开；
    后端监听非回环地址时启动告警。
- 文案移除「90 秒出片」承诺，明确异步排队和恢复能力。

### 第二阶段：质量生产链

- 队列依赖、任务超时与有限重试、首帧质量门。
- 角色/场景设定自动生成与持久化。
- 镜头版本、选中版本、单镜重试与失败范围重跑。
- 质检指标改名并拆分真实性。

### 第三阶段：画布成为项目工作面

- `canvas_documents`、实体引用、旧存档迁移。
- 参数记忆、统一撤销、多选批量、邻接索引。
- 项目各实体到画布节点的双向深链。

### 第四阶段：官方模型服务

- 官方令牌认证、云端账单与配额、真实 usage 回传。
- 本地 `official/byo/mock` 三通道费用语义与展示。
- 模型路由、质量模板、失败分类、用量与成本看板。
- 官方服务侧内容安全与滥用防护；本地诊断默认 opt-in，不静默上传用户剧本和素材。

## 6. 本地优先版本的运营与合规边界

- 默认不采集行为数据；如需要改进产品，提供明确 opt-in 的匿名遥测，并能查看与关闭。
- 错误日志、任务 ID、Provider 配置和诊断信息保存在本地，提供一键导出；上传前由用户确认。
- 官方通道必须做账号级限流、内容安全、审计与账单；这些不能只靠开源本地代码执行。
- AI 生成内容标识与品牌水印分开处理：不以强制品牌水印损害本地创作，但提供符合目标发布地区要求的 AI 标识能力。
- 自部署用户的剧本、素材和 Key 默认不离开本机；只有所选生成通道所需的数据才发送给对应供应商。

## 7. 明确不做

- 不做本地授权 DRM，不尝试从本地数据库证明用户是否超过 10 万商业价值。
- 不强制联网、不强制官方 token、不削弱 BYO 和 mock。
- 不把本地估算成本包装成官方真实账单。
- 不用 priority 代替任务依赖，不用无限重试假装异步可靠。
- 不要求新手先学画布，也不让画布继续成为独立数据孤岛。
- 在正确性、持久化和质量闭环完成前，不继续增加平行画布、平行聊天入口和展示型页面。
