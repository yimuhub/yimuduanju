## 0. 一句话结论

**后端流水线是这个项目最扎实的资产，前端体验和运营基建是最大的负债。**

九段流水线、服务端任务队列、幂等批量生成、SSE 降级轮询、画布↔工作台双向深链——这些是很多同类产品做不出来的东西。但同时存在：一个能读走 `.env` 的接口、一个会把已付费产物静默覆盖的交互、一个首屏点了没反应的主入口、一套 5 条轨道的假时间线、以及零身份 / 零埋点 / 零支付的运营底座。

当前形态适合「**个人本地 / 私有化部署 + 自带 Key**」，不适合对外承接多用户 SaaS。

### 评分卡

| 维度 | 评分 | 依据 |
|---|---|---|
| 后端流水线与任务可靠性 | **B+** | 队列、幂等、崩溃恢复做得比同类好；但结算非原子、无超时 |
| 安全 | **D** | 任意文件读取、身份头可伪造、SSRF 守卫有缺口 |
| 前端体验（重度用户） | **C** | 画布能力强，但无批量、无撤销、参数不记忆 |
| 前端体验（新用户） | **D+** | 首屏主按钮断链、术语墙、错误文案给程序员看 |
| 产品完整度 | **C** | 功能密度高，但 3 处假实现 + 多处半成品未标注 |
| 运营基建 | **F** | 无用户、无事件、无支付、无合规标识 |

## 2. 五个视角各自最重要的发现

### 2.1 产品经理视角：主路径断在第 5 步

**「一句话出片」真实要 9 步、跨 3 个页面、2 段异步等待，且第 5 步是硬断点。**

| 步 | 动作 | 断点 |
|---|---|---|
| 1 | 首页输入一句话 | 只有「做/拍/来一部…剧/视频」正则才触发建项目（`AgentStudio.tsx:329`），其他表述走闲聊 |
| 2-3 | 确认开拍计划 → 停在聊天 | ✔ `:567` 弹窗根本不渲染 |
| 4 | 手动点项目卡 | 落地是「概览」，不是「流程总控」（`app.tsx:101`） |
| 5 | 自己发现左侧「流程总控」 | **首页显示「等待确认」但不给确认按钮**（`AgentStudio.tsx:487`），唯一的 `approveProject` 调用在 `ProjectFlowTab.tsx:102` |
| 6-8 | 三道确认门 | 每道门都要回同一页刷新等待 |
| 9 | 导出合成 | 浏览器 FFmpeg 需跨域，大概率失败后转服务端 |

**功能半成品清单**（都应「补完或明确下线」，不能挂着不动）：

| 功能 | 证据 | 现实 |
|---|---|---|
| 时间线 | `ProjectTimelineTab.tsx:157-205` ✔ | 5 轨同一批数据 |
| 3D 导演台摆位 | `Director3D.tsx:308-317` | 组件内 state，关掉即重置 |

**该补的 3 个**：主路径闭环、画布服务端持久化、角色/设定集的生产闭环。

### 2.2 工程师视角：P0 是「能读走密钥」，不是「代码丑」

按 ROI 排序的五个真问题：

1. **任意文件读取**（上文 #1）—— 改动约 20 行，收益最大。
2. **身份可伪造 + 零授权**（上文 #2/#3）—— `req.userContext.userId` 全仓只用于打日志（`projects.service.ts:259/327/353`），从不用来限制查询。
3. **SSRF 守卫有洞**：`url-guard.ts:13-14` 注释明写「BYO 供应商 baseUrl 不走此守卫」，而 `providers.service.ts:381-430` 的 `test-connection` 会把任意 baseUrl 真实打通并回显状态码与错误文本 → 内网端口扫描器。
4. **媒体下载器两套**：`export.service.ts:903-940` 做了 `--proto` 守卫，`job-worker.service.ts:1612-1669` 的 `archiveLocalFile` 什么都没做，且落盘到 `/uploads/` 静态目录。
5. **结算/预算不原子**（上文 #8/#9）—— 金额 bug 一旦上线就是对外账单，回滚成本极高。

**架构负债**：
- 单文件状态爆炸：`Director3D.tsx` 2182 行 / 40 个 `useState`；`ModelDialog.tsx` 1237 行 / 37 个；`ProviderSection.tsx` 1450 行 / 25 个。这些文件没法测、没法改。
- 供应商协议实现 3 遍（`model-gateway.service.ts` / `pavo3.service.ts` / `providers.service.ts` 探测版），超时策略已经漂移（180s vs 无）。
- **所有 `fetch` 无 timeout**（`model-gateway.service.ts:127/461/579/650/814`）：上游挂起就永久占用 worker 槽，并发上限只有 8。
- 重试判定靠字符串匹配：`job-worker.service.ts:403-422` 用 `message.includes('未配置')`、`/\b503\b/` —— 模型正文里带 "503" 会无限重试。
- 索引缺失：`generation_jobs` 无索引，而 worker 每 10s 按 `status+priority+created_at` 扫表；`projects.created_at`、`assets.project_id`、`shots.project_id` 同样没有。
- **交付形态不匹配**：`Dockerfile` runtime 层没装 ffmpeg，但服务端合成强依赖它；`uploads` 未挂卷，重启丢全部产物。
- 依赖错位：`react` / `tailwindcss` / `zustand` / `three` 全在 `devDependencies`；`xlsx/echarts/jspdf/framer-motion/gsap/slate/redux` 零引用却仍在安装。

**工程基建**：测试 3 个文件 332 行，`npm test` 是 `--passWithNoTests`，`test:e2e` 直接 `echo`；无 CI；`GlobalExceptionFilter` 对未知异常只回「服务器内部错误」**且不记日志**（`exception.filter.ts:86-95`）；无 `/health`。

### 2.3 重度用户视角：不是缺功能，是「无声地毁掉我的工作」

按「会让我立刻弃用」排序：

1. **3D 截图覆盖已付费产物**（上文 #5）—— 不只是丢图，是覆盖你刚生成好的首帧图。
2. **localStorage 写满后静默停止保存**（上文 #7）—— 截图 `toDataURL` 一张 1-3MB，配额 5MB，两三张就满。界面照常跑，刷新全丢，全程无提示。
3. **生成参数关窗即归零**：`ModelDialog.tsx:229-242`（图片）/ `:570-586`（视频）全是弹窗内 `useState`，`runGeneration` 从不回写 `node.data.gen`。调好的「8s / 16:9 / 负面词」重开就变回默认。
4. **全站除画布外没有撤销**：`ProjectStoryboardTab.tsx:233-245` 删镜头直接 `filter`；`ProjectTimelineTab.tsx:74-96` 拖时长即改即存；`ProjectDirectorTab.tsx:94-107` 每次点击即 PATCH。
5. **Redis 队列模式下「先图后片」失效**：`storyboard.service.ts:755` 靠 priority 75/65 排序，但队列模式认领 SQL 是 `orderBy(createdAt)`（`job-worker.service.ts:256-263`），**完全忽略 priority**；单机模式才用了 priority（`generation.service.ts:303`）。生产环境反而没有顺序保证 → 视频找不到首帧 → 退化成文生视频，钱照扣。

**别扭但能忍的**：快捷键文档写了一半没实现（`pavo3Constants.ts:411-451` vs 实际 6 个，`FreeCanvas3Page.tsx:298-325`）；`⌘Z` 不含拖拽，会把布局弹回上一次结构操作前；分镜「批量生成」取全量而非筛选结果（`ProjectStoryboardTab.tsx:122-135`），筛到某场景点「生成 38 镜」实际给 120 镜扣费；时间线没有播放头/不能播放/不能排序；镜头顺序分镜页用 `shotNumber`、时间线用 `sortOrder`，改完 A 页 B 页不动；200 节点时每次 store 写入触发 O(V²E) 全图遍历（`Pavo3Node.tsx:125` 订阅 `getUpstreamRefs`）。

**做得对、别改坏的 5 个**：服务端队列 + 崩溃恢复（`job-worker.service.ts:176-197`）、批量生成幂等去重 + 事务（`storyboard.service.ts:628-644`）、SSE + 断线降级 + 页面不可见不刷、画布↔工作台深链与产物自动回写、预算硬门 + 诚实文案（「远端可能继续计费」）。

真实旅程的关键节点：

- 空状态一律补一个主按钮（分镜页现在只有一行「暂无分镜，请先生成分镜故事板」）

**术语墙**：制作圣经 → **设定集**；分镜 → **镜头清单**；景别 → **镜头远近（全身/半身/特写）**；运镜 → **镜头怎么动（推进/摇/固定）**，并给「自动，交给 AI」默认值；供应商/Provider/通道/Base URL → **AI 服务账号** + 一句「就像给剪映开会员」。

### 2.5 运营视角：零身份 + 零事件 + 零支付

**最刺眼的一点：漏斗接口已经写好了，但没有任何页面调用它。**

`dashboard.service.ts:313-404` 实现了 `funnel-health`（创建→剧本→分镜→首帧→视频→成片 + 通道健康度 + 错误归因），`client/` 全目录 grep `funnel` **零命中**。这是纯粹的死代码，也是半天就能变现的资产。

**明天上线会踩的坑**：
1. 1000 人共用一个 `local-user`，互相能看到并删除对方的项目。
2. 所有失败都是黑盒：500 不记日志、`generation_jobs` 只有一段 `error_message` 文本、无 user_id、无 errorCode。用户说「第 7 镜卡住了」，客服只能让他截图。
3. **一个重度用户打穿全局预算，全平台冻结**：`budget-cap.service.ts:28-56` 的 `getMonthlySpend()` 是全站 SUM，没有 `WHERE user_id`（也没有这个字段）；超限后 `job-worker.service.ts:200-215` **直接停止认领**，其余用户全部卡在「排队中」，而提示语是写给运维的「请上调 MONTHLY_BUDGET_CAP_CNY」。
4. 预算守卫不预留不锁，1000 人并发全部放行；且 `cost` 只在成功时写入，失败任务与在途任务对预算完全隐形 —— 真实花 1 万，账面可能只有 3 千。
5. 导出在同步请求里跑本机 ffmpeg（`export.controller.ts:13-21`），10 个人同时点就能把整站拖死。

**商业化的结构性问题**：定价单位是「次」，成本单位是「秒」。`0001_billing.sql:31-42` 全部价格行 `unit='call'`，`billing.service.ts:78-90` 只按 `job_type + tier` 取价，**不接收时长**。4 秒镜头和 60 秒镜头记同样的钱。毛利算不出来——因为没有分子（无支付、无余额、无订单），分母也失真。

**合规红线**（这块最容易被忽略但后果最重）：
- **AI 生成内容标识完全缺失**。`export.service.ts` 合成成片不做任何角标、不写文件元数据、无数字水印；`getPublishPack()` 只生成一段带 `#AI短剧` 的文案，话题标签不是《AI生成合成内容标识办法》要求的显式标识。
- **内容审核只有一个 8 词正则**（`pavo3.service.ts:79`），只在 `pavo3.generate()` 里校验；主流程 `storyboard.service.ts` 的 12 处 `assertAllowed` **无一处做内容校验**。且只过滤提示词，不审图、不审视频。
- 无用户协议、无隐私政策、无账号注销、无数据导出入口。

## 5. 需要你拍板的三个产品决策

这三个问题不是代码能回答的，但答案会决定上面一半工作的方向。

1. **这东西到底是「本地工具」还是「在线 SaaS」？**
   如果是前者：身份、支付、多租户、埋点可以全部不做，P0 里 #2/#3 降级为「只允许 loopback」，把力气全放在画布和批量上。
   如果是后者：`gateway.js` 那套身份代填必须整个删掉换真登录，`AccountPage` 的假套餐必须下线，否则是虚假承诺。

2. **「一句话 90 秒出片」和「三道人工确认门」哪个是产品承诺？**
   现在文案承诺前者（README:9），流程强制后者（`projects.service.ts:549-556`）。二选一：要么把确认门做成默认跳过 + 失败再看，要么把文案改成「一句话生成初稿，三次确认后出片」。

3. **画布是主入口还是彩蛋？**
   它现在是唯一「真有创作感」的界面，但数据在 localStorage、参数不记忆、无批量。如果它是主入口，P1 里的画布落库应该提到 P0。
