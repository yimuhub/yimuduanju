**过程中发现并当场修复的真实 bug（3 个，均为"真实 API 才暴露"）**：
1. **上游限流固定 20s 重试过于激进**（Agnes 视频队列满 503，日志 63 次重试记录）→ 改为按 provider 指数退避 20s→40s→…→300s 封顶，成功清零（job-worker.service.ts）
2. **状态查询 429 被当成生成失败**消耗重试次数 → 429/503 改判 rate_limit，不消耗重试（model-gateway.service.ts）
3. **状态查询无节流**：多页签/SSE 并发把查询次数放大触发 Agnes 独立的查询限流 → 同任务 8s 轮询节流（generation.service.ts）

## 一、资深开发工程师维度（7.9/10，较上轮 +0.1）

**实测操作**：全量读取 server/ 19 模块与 job-worker 流水线；curl 直测三方 API 三类生成；审查限流/重试/轮询三处运行时行为。

- ✅ **达标**：真实 API 压力下状态机行为正确（限流不消耗重试、退避、自动续跑）；三道门+门序校验在真实数据下工作；SSE/轮询双通道一致；限流按 provider 维度隔离（图片通道不受视频队列满影响——8 张图同期全部成功即为实证）。
- 🔧 **本轮修复**：上述 3 个真实 bug + 指数退避。
- ⚠️ **改进建议**：①任务级轮询分散到 worker tick 而非请求触发（当前多页签会放大查询）；②视频并发建议按 provider 信号量限 2-3 路，减少上游 503 概率；③补 job-worker 的单测（限流退避/自动链）。

## 二、资深产品经理维度（8.3/10）

**实测操作**：完整走 开拍→计划卡→两道门→工作台全 Tab→画布→导出；双模式切换。

- ✅ **亮点**：计划确认门把成本与步骤亮在前面（真实 Key 下尤其实用——用户敢点）；流程总控/画布/任务四处进度同源；三道门的"人审关键产物"设计符合生产级 AI 内容工具的最佳实践。
- ⚠️ **缺口（按优先级）**：①协作/分享（成片交付给客户仍靠文件）；②角色一致性自动审计（LOCK 体系有了，缺跨镜检测自动化）；③发布闭环（一键发抖音/TikTok）。

## 三、重度用户维度（7.5/10）

**实测操作**：以"每天出 3 条片"的工作室主理人视角连续操作 5 个项目。

- ✅ **顺手**：开拍后几乎零操作等到分镜门；画布自动落产物+节点状态实时徽章（真实任务验证 2 秒内出图）；导出全家桶（MP4/剪映草稿/SRT/ASS）。
- ⚠️ **痛点**：①视频单条 5-10 分钟时 8 条串行等 40 分钟+——建议预演/定稿两档并发策略；②失败镜头的"重试全部失败"在队列满时会把坏时机放大（配合退避已缓解）；③成本预估尚缺"视频按秒精确预估"。
