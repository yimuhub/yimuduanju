# Studio 全功能编辑与多轨素材升级 · 实施方案

- 日期：2026-11-16
- 分支：`feature/studio-pro-edit-v1`（已从 `main` 创建，本轮不含代码提交）
- 范围：时间线跨轨拖拽、字幕就地编辑、三类素材导入、全功能编辑模式 + 浮动对话入口 + Agent 剪辑
- 原则：**同一数据源（`timeline_clips` / EDL）不变**；对话与面板共用同一套 API；新增功能不删减既有能力

---

## 0. 结论速览（诚实评估）

| 需求 | 判定 | 关键原因 | 工作量预估 |
|---|---|---|---|
| 1. 画面片段拖到别的轨道、自动开新轨、不覆盖原轨 | **可直接实现** | 纯前端落点计算 + `tracks` 元信息；不改表结构（仅补 `order/role`） | 2–3 天 |
| 1b. 多条画面轨“真正叠加合成”（画中画/透明度/混合） | **一期不可直接实现** | 现有导出把所有 `track=video` 的片段按时间**串行 concat**，`overlay` 轨根本不渲染；要重写导出为 filtergraph 合成 | 二期 5–8 天 |
| 2. 字幕单击进入、双击编辑内容 | **可补齐（当前是缺陷）** | 双击只 `setSubEdit`，**输入框从未渲染**（`subEdit` 是死状态），`.tl-sub-input` 样式与提交函数都在，只差 UI 与状态机 | 1–2 天 |
| 3a. 本地素材导入（≤25MB） | **可直接接 UI** | `POST /api/projects/:id/uploads` 已存在（octet-stream，白名单，25MB 上限） | 1–2 天 |
| 3a. 本地大文件（>25MB） | **需新增服务能力** | 现接口硬拒 25MB；对象存储预签名是**桩**（未配置返回空） | 分片上传 3–5 天 / 接对象存储另计 |
| 3b. 其他任务产生的可复用素材 | **查询已具备，引用要补** | `/api/assets` 支持按项目/类型/关键词分页；但**无用户/租户隔离**，且无“引用”记录 | 2–3 天 |
| 3c. 资产包素材 | **现无此概念，可自研** | 需要新表 + zip 导入导出 + 许可字段；仓库无 zip 依赖 | 5–7 天 |
| 4a. 全功能编辑模式（左栏保留、中间对话区取消、编辑区直接可用） | **可直接实现** | `StudioShell` 是纯 CSS Grid（rail/stage/dock/timeline），加一个 `edit` 视图即可 | 3–4 天 |
| 4b. 浮动 logo/桌宠入口，任意位置拖拽，点击继续对话 | **浏览器内可实现** | 复用 `CanvasFloatingNav` / `AssistantPanel` 的浮层经验 | 2 天 |
| 4b. 系统级桌面宠物（脱离窗口、透明置顶） | **Web 端不可实现** | 需要 Tauri 透明置顶窗口 + 客户端权限，当前 Web 形态做不到 | 客户端专项 |
| 4c. 通过对话让 Agent 直接剪辑已产出内容 | **可做“结构化提案 + 确认门 + 事务应用”** | 文本网关**无 function calling**（只有 `generateText/streamText`），现有动作协议仅 `update_shot/update_script`，且主对话面板**没渲染动作卡** | 3–5 天 |
| 4c. Agent 全自主连续多步剪辑 | **不可实现（当前架构）** | 没有工具执行循环、没有回放校验；“直接改”会绕过确认门，违反项目红线 | 需 Agent 执行器专项 |

> 一句话：**1、2、4a、4b(浏览器内)、3a(小文件) 可以做实；1b、3a(大文件)、3c、4c(全自主) 要么需要新管线，要么当前架构不支持**。方案里对每一项都给了降级/替代路径。

## 1. 现状核查（代码级事实）

### 1.1 布局与视图
- 主骨架：`client/src/components/studio/StudioShell.tsx`
  - Grid：`rail | stage | dock`，底部 `timeline`，最下 `statusbar`（样式见 `client/src/styles/graphite.css` 的 `.app`）。
  - 视图三态：`chat | canvas | page`（`StudioStage.tsx`）。**没有“编辑模式”**。
  - 左导航：`StudioRail.tsx`（品牌、项目列表、任务、用量）——需求要求“保持不变”，可直接复用。
- 右坞：`StudioDock.tsx`，8 个 Tab（预览/剧本/圣经/道具/分镜/资产/质检/导出），预览用 `StudioPreview.tsx`。
- 沉浸式先例：`FreeCanvas3Page` + `CanvasFloatingNav`（左上角悬浮导航）、`AssistantPanel`（右下悬浮 AI 面板）——浮动入口有现成交互范式。

### 1.2 时间线 / EDL
- 唯一真源：`GET/PUT /api/projects/:projectId/timeline`（`server/modules/timeline/timeline.controller.ts`）。
- 前端编辑通道：`client/src/components/studio/useEdlEditor.ts`
  - 所有变更走 `commit()`：乐观更新 → **400ms 防抖 PUT 整文档** → `expectedVersion` 乐观锁，409 进入 `conflict`。
  - 撤销/重做：EDL 快照栈 + IndexedDB（`client/src/lib/timeline-history.ts`）。
  - 已有能力：移动、修剪、分割、波纹删除、变速、音量、转场、锁定、绑定组、字幕样式、复制粘贴、标记点、轨道增删改、音画分离、`packVideo`。
- 轨道模型（`shared/api.interface.ts`）
  - `TimelineClip.lane`：同类型轨道内的分层下标；`TimelineTrackMeta { track, lane, name, muted, solo, locked, height }`。
  - 行渲染：`StudioTimeline.tsx` `rows`（subtitle → video → audio → overlay，按 lane 升序），`V1` 即 `lane=0`。
  - 上限：`addTrack` 到 `lane>19` 返回 null（20 条封顶）；但 DTO 允许 `lane=20`，存在 1 个边界不一致。
- **关键缺陷（会影响下面 2/4 两项）**：`saveDocument()` 每次保存 **先 delete 全部 clips 再 insert**，`id` 由服务端重新生成，而 `toSaveClip()` **不回传 id**。后果：
  1. 自动保存 0.4s 后，`selectedIds` 指向已不存在的 id，属性条会“自己消失”；
  2. 内联字幕编辑若以 `id` 为锚点，保存瞬间失焦/错位；
  3. Agent 提案若以 `id` 定位，保存后立刻失效。
  → **所有新功能必须先补“稳定片段标识”**（见 §2）。

### 1.3 拖拽落点
- `client/src/lib/timeline-drop.ts`：`pickFreeLane()`（首尾相接不算重叠；被占则往下找空 lane；全满 `maxLane+1`）、`laneFromY()`（**落在最后一行以下 = 新建**）。
- 素材跨面板拖入：`timeline-dnd.ts` + `StudioTimeline.computeDrop()`；`dragover` 阶段用模块级变量兜底（浏览器限制）。
- **已有片段拖动**（`startMove`）：只认 `document.elementFromPoint()` 命中的 `.trk` 行；落在空白区 → `target=null` → `deltaLane` 回退 `origLane`。**结论：现有片段向下拖到空白不会开新轨**，且拖到已有轨道**不做碰撞检测**（允许同 lane 同时刻重叠）。
- `moveClip` 只改自身 `lane`，不动别人 —— “不覆盖原轨道”已在数据层成立。

### 1.4 字幕
- 数据结构：`TimelineClip.text` + `textStyle`（归一化坐标、字号按短边百分比）；默认样式 `DEFAULT_TEXT_STYLE`。
- 预览：`StudioPreview.tsx` 按播放头筛 `track=subtitle`，用 DOM 渲染（z-index/坐标/描边），**多字幕轨会同时显示**。
- 导出：`timeline.service.ts` `buildSrt` + ASS 烧录（`burnSubtitles`，失败回退软字幕）。
- **缺陷**：`StudioTimeline` 里 `subEdit` 只有 `set` 与 `commitSubtitle`，**渲染树里没有 `.tl-sub-input` 输入框**（全局 grep 仅在 CSS 与 `onPointerDown` 忽略列表中出现）。即“双击改字幕”目前**没有任何可见编辑入口**，只能改样式。

### 1.5 素材 / 资产
- 资产表：`assets`（`projectId`、`assetType`、`fileUrl/filePath`、`durationSeconds`、`sourceType`、`metadata`…）。
- 列表：`GET /api/assets`（`projectId/assetType/keyword/page`），`GET /api/assets/by-project/:id`，全局资产页已支持“全部项目”筛选。
- 上传：`POST /api/projects/:id/uploads`（二进制、`X-Filename`、`durationSeconds`）
  - 白名单：webm/mp4/png/jpeg/mp3/wav/m4a；**25MB 上限**；60s 超时；落 `data/uploads/<projectId>/<uuid>.<ext>`；登记 `sourceType='whitemodel'`。
- 对象存储：`storage.service.ts` 预签名是**桩**（无 S3 配置时 `mode:'local'`、`uploadUrl:''`）。
- 资产包：全局检索无 `assetPack` 概念（仅在人物“视觉资产包”语义里出现）。
- 跨项目复用：文件 URL 可直接被时间线片段引用（`sourceUrl` 支持 `/uploads/...`），但**没有引用记录/权限校验**；`assets.list` **没有用户/租户过滤**（本地单用户可用，企业多用户是风险）。

### 1.6 对话与 Agent
- 会话与流式：`assistant.service.ts`（`POST /api/assistant/sessions/:id/messages/stream`，SSE）。
- 文本能力：`model-gateway.service.ts` 只有 `generateText / generateTextWithUsage / streamText`，**没有 tools / tool_choice**。
- 动作协议：后端 system prompt 注入 ```yimu-action```，前端 `client/src/lib/agent-actions.ts` 解析，白名单仅 `update_shot`（12 个字段）与 `update_script`。
- **主对话面板未接动作卡**：`StudioChat.tsx` 不调用 `parseAgentActions`；只有 `AgentStudio` / `ProjectAgentsTab` 用 `AgentActionCard`。所以“在项目对话里让 Agent 改东西”目前**连 update_shot 都不会出现确认卡**。
- 内置 Agent 注册表（`agents.registry.ts`）给“剪辑助手”声明了 `tools:['timeline','export-jianying']`，但**只是文案标签，没有执行器**。

### 1.7 导出真实能力（决定功能 1 的边界）
- `exportTimeline()`：`videoClips = all clips where track==='video'` → **按 `timelineStart` 排序、逐段 trim、统一编码、`concat` 拼接**。
- 结果：**轨道分层不参与合成**。同一个时刻 V1/V2 两条画面 → 成片里会**前后各播一遍**（总时长变长），不是叠加。
- `audio` 多轨会 `adelay + amix`（正常混音）；`subtitle` 全部进同一份 SRT/ASS；`overlay` 轨**本期不渲染**。
- 预览同理：`StudioPreview.activeVideo` 取“当前时刻最后一个”视频片段，**不做叠加**。

> 这一条是本方案最重要的诚实边界：**“拖到新轨道”在编辑器里成立，但在成片里目前没有“分层”语义**。必须用导出模式开关把语义讲清楚，否则用户会认为“拖上去就叠化了”。

## 2. 前置改造（P0，所有功能的地基）

### 2.1 稳定片段标识 `clientKey`
**问题**：服务端每次保存重建行、重生成 UUID，前端所有“指向某片段”的引用（选中、内联编辑、Agent 定位、撤销项）都会在 0.4s 后失效。

**方案**
1. 迁移 `0029_timeline_client_key.sql`
   - `ALTER TABLE timeline_clips ADD COLUMN client_key text;`
   - 唯一索引：`CREATE UNIQUE INDEX ... ON timeline_clips(project_id, client_key) WHERE client_key IS NOT NULL;`
   - 历史数据回填：`client_key = id::text`（幂等）。
2. `TimelineClip.clientKey: string`（新增，必填返回）。
3. `SaveTimelineClipDto.clientKey?: string`（`@IsString @MaxLength(64)`），`toSaveClip()` 回传；`saveDocument` 写入；`mapClip` 返回。
4. 前端：`useEdlEditor` 内所有 `selectedIds / 撤销条目 / 内联编辑锚点` 改用 `clientKey`；`id` 仅作后端行标识。
5. 兼容：老数据无 `clientKey` 时用 `id` 兜底（`clipKey(c) = c.clientKey ?? c.id`）。

**顺带修复**：`flush()` 成功后按 `clientKey` 重映射 `selectedIds`，解决“自动保存后选中丢失”。

### 2.2 轨道显示序号与排序（为功能 1 服务）
新增 `shared/timeline-order.ts`（纯函数，可单测）：
- `displayIndex(tracks, clips)`：同类型轨道按 `order ?? lane` 排序，空 lane 不占号；
- `trackCode(track, index)`：`V1..Vn / A1..An / S1..Sn`；
- 行渲染、轨道头、导出提示、Agent 上下文**全部走它**，禁止再各自 `lane+1`。

`TimelineTrackMeta` 新增（全部可选，向后兼容）：
```ts
order?: number;          // 显示顺序（缺省 = lane）
role?: 'main' | 'alt' | 'overlay';  // 画面轨语义：主链 / 备选 / 叠加（一期只用 main/alt）
exportEnabled?: boolean; // 该轨是否参与导出（缺省 true；画面 alt 轨一期缺省 false）
```

## 3. 功能一：画面片段跨轨拖拽 + 自动开新轨

### 3.1 目标语义（按用户描述固化）
> V1 里已有 3–4 个视频；拖其中任意一个向外到别的轨道 → **自动生成一条独立新轨**，原 V1 里其余片段**位置/内容不变**（留下空位），新轨与原轨并存。

补充定义：
- “向外”= 向下拖到同类型轨道的空白行 / 最后一行下方；
- 新轨**默认插在同类型轨道末尾**（V1 下面依次 V2、V3…）；
- 不留空位不是默认行为；闭合空位用“波纹删除 / 画面轨排齐”（已有 `packVideo`）。

### 3.2 拖拽判定（重写 `startMove` 的纵向部分）
**不再依赖 `elementFromPoint`**，改为几何命中，保证拖到空白也能算：

```
输入：pointerY（相对轨道画布顶部，已减 16px 标尺）、rows、pxPerSec、scrollLeft
1. lane = laneFromY(rows, pointerY, track)   // 命中行 → 该 lane；空白 → maxLane+1
2. 计算落点时间 t = quantizeToFrame(clamp((startX 位移换算), 0, ∞))
3. 碰撞检测：同 track、lane 上，是否存在别的片段满足
   other.start < t+span-EPS && t < other.end-EPS
   排除：自己、绑定组伙伴（纵向不联动）
4. 若被占：
   pickFreeLane(occupied, lane, t, t+span)
   → 优先同一时刻的空 lane；全占则 maxLane+1（created=true）
5. 若 lane 超出上限 19 → toast「轨道已达上限（20 条）」并回退原 lane
6. Alt 按下 = 强制允许同 lane 重叠（给“交叉淡化/叠化”预留），否则永不重叠
```

**拖动中的视觉反馈**
- 目标 lane 已存在：该行整行高亮 + 竖向插入线；
- 目标 lane 不存在：在行列表末尾渲染一条 **24px 占位“新建 V2”** 虚线行（`dropHint` 已有 `created` 样式，修掉 `rowTop` 缺失时 `??16` 的错位）；
- 跨类型（拖到字幕/音频行）：显示禁止光标 + 提示“只能拖到同类型轨道”，松手回退。

### 3.3 落库（一个新事务式提交）
`useEdlEditor` 新增 `moveClipToLane(id, start, lane, { create: boolean })`：
1. `ensureTrack(track, lane, { role, height, order })`：写 `doc.tracks`（不依赖 `addTrack` 的“连续末尾”假设）；
2. 更新该片段 `lane + timelineStart`；
3. `commit()` 一次 → 400ms 后整体 PUT（`tracks` 与 `clips` 同一次保存，不会出现“轨建了但片段没过去”的中间态）；
4. 撤销栈一条：`移动到 V2（新建轨道）`。

**不覆盖保证（数据层）**
- 只改被拖片段的 `lane/timelineStart`；
- 其它片段对象引用不变（`map` 返回原对象）；
- 服务端整体替换时按传入值写入，不做隐式重排。

### 3.4 轨道排序规则
- 插入：同类型最大 `order/lane` + 1 → 显示在同类型最下方；
- 手动排序（同类型内上下移动）列为 **Phase 1.5 可选**：轨道头上下箭头 → 改 `order` → 行重排；片段 `lane` 不动（避免级联改数据）；
- 删除空轨：允许；`lane` 留空洞但显示序号连续（靠 §2.2）；
- 命名：`V1..Vn` 由显示序号生成，不再 `lane+1`。

### 3.5 异常处理清单
| 场景 | 行为 |
|---|---|
| 拖出时间线区域外松手 | 取消，回到原位（无写入） |
| 拖到字幕/音频/overlay 行 | 回退原轨 + toast 说明 |
| 目标片段/轨道 `locked` | 拒绝拖动，提示先解锁 |
| 目标 lane 有时刻重叠 | 自动下移/新建，绝不覆盖 |
| 同 lane 已有交叉（历史脏数据） | 允许保留，但拖入时强制选空位；导出给 warning |
| 轨道数达 20 | 拒绝并向用户说明上限 |
| 拖动中触发自动保存 | 拖动期间 `busyRef` 挂起 `schedule()`，drop 后一次保存 |
| 保存 409 | 保留本地结果 + 顶部冲突条；不静默覆盖服务器 |
| 拖动中刷新/SSE 覆盖 | 现有 `timelineTouchedRef` 已防；补 `dirty` 时禁止 reload |
| 多选拖动 | 一期仅横向整体移动（现有 `moveClips`）；跨轨仅单片段，提示“多选不支持换轨” |
| 绑定组 | 横向联动保留；纵向换轨**只动被拖片段**，属性条注明“绑定不跨轨” |
| 高倍缩放 / 横向滚动 | 坐标换算统一用 `canvasRect + scrollLeft`，拖动开始快照 `scrollLeft`，避免抖动 |
| 拖拽中途项目切换 | 取消拖动并 flush 或丢弃（现项目切换逻辑已有） |

### 3.6 导出语义（必须同时改，否则是“假功能”）
新增 `ExportTimelineDto.videoLaneMode`：
```ts
videoLaneMode?: 'sequence' | 'main';   // 默认 'sequence'（= 现状，保证老项目零变化）
```
- `sequence`：所有画面轨按 `timelineStart` 串行拼接（当前行为）；
- `main`：只取 `role='main'`（缺省 lane 0）的画面链，其它轨忽略；
- UI：导出面板出现“画面轨处理”单选，并在存在 `lane>0` 画面片段时显示提示：
  “V2 及以上画面轨当前不参与成片合成（仅编辑器内分层）”。
- `overlay`（真正叠加合成）**不在本期**，见 §7 二期。

## 4. 功能二：字幕单击进入 / 双击编辑

### 4.1 交互定义
- **单击**：选中片段（高亮）+ 属性条出现（字体/字号/颜色/描边/位置）+ 播放头跳到字幕起点；**不进入输入态**、不触发拖动（现有“首次点击不拖动”保留）。
- **双击**：进入就地编辑（clip 内浮层 `textarea`），自动聚焦、全选、光标在末尾；Esc 取消、Enter 提交、Shift+Enter 换行（ASS 用 `\N`）。
- **点击空白/其它片段**：提交当前编辑（blur 提交）；点击另一条字幕 = 先提交再进入新条。
- 键盘：选中态按 `Enter` 等价双击；`F2` 亦可。

### 4.2 状态管理
单一状态源放在 `useEdlEditor`（不放组件内，避免与撤销/保存脱节）：
```ts
subtitleEdit: {
  clipKey: string;      // 稳定标识（clientKey）
  draft: string;        // 未提交文本
  origin: string;       // 进入编辑时的原文（用于 Esc / diff）
  startedAt: number;
} | null
```
状态机：
```
idle → selected（单击） → editing（双击/Enter） → committing（Enter/blur）
     → saved（成功） | conflict | error → 回 editing（可重试）
```
- 播放开始时：若 `editing` → 先 blur 提交，再播放（避免输入框被播放头带走）。
- 切换右坞 Tab / 项目：先提交；项目切换弹确认（未保存草稿）。

### 4.3 保存时机（明确写死）
| 时机 | 行为 |
|---|---|
| Enter / blur | 提交：本地乐观更新 + 入撤销栈（**一次编辑 = 一条历史**，不是每字符） |
| 停止输入 400ms | 只更新本地草稿，不落库（避免每个字一次 PUT） |
| 全局自动保存 | 提交后由 `commit()` 触发 400ms 防抖 PUT |
| 播放 / 分割 / 删除 / 拖动前 | 强制 flush 当前字幕草稿 |
| 导出前 | `saveNow()`（已有） |
| 关闭页面 | `beforeunload` 提示（仅 dirty 时） |
| 文本为空 | 允许保存空串；预览不渲染、导出跳过；toast 提示“空字幕不会出现在成片” |
| 超长文本 | 软上限 120 字/行；超出只警告不截断（导出可能溢出，需在预览提示） |

### 4.4 冲突处理
文档级乐观锁（`expectedVersion`）不变，但要**字幕级重基**，不能整页丢改动：
1. 收到 409：
   - 若当前处于 `editing`：**不关闭输入框、不覆盖草稿**；
   - 拉取服务器最新文档（`getTimeline`）；
   - 用 `clientKey` 找到同一条字幕：
     - 找到 → 把 `draft` 作为 patch 应用在服务器文档上 → 用服务器 `version` 重试一次 PUT；
     - 找不到（被删）→ 提示“该字幕已在别处删除”，提供「另存为新字幕」/「丢弃」；
     - 锁定 → 提示并只读展示。
   - 重试仍 409 → 进入冲突条，交用户选择「保留我的 / 载入服务器」。
2. 双窗口同时编辑同一条：后保存者触发上述重基；若服务器文本已被改，diff 展示两版并让用户选（不静默）。
3. 删除/波纹删除正在编辑的片段：先提交再删；若删除已发生 → 关闭编辑 + toast。
4. 撤销：字幕编辑入栈；撤销恢复原文本并保持选中；跨保存的撤销用 `persistEntry` 同款思路（按 `clientKey` 定位）。

### 4.5 实现要点（补上缺失的 UI）
`ClipView` 内新增：
```tsx
{isSub && subtitleEdit?.clipKey === clipKey(clip) ? (
  <textarea
    className="tl-sub-input"
    autoFocus
    value={draft}
    onChange={...}
    onBlur={commit}
    onKeyDown={（Enter 提交 / Esc 取消 / 阻止冒泡）}
    // IME：onCompositionStart/End 时 Enter 不提交
  />
) : null}
```
- 阻止 `onCanvasPointerDown` 把输入框当画布点击（现有 `.tl-sub-input` 忽略已留好，但对象要改成 textarea）；
- 编辑态禁止拖动该 clip（`pointerdown` 直接 return）；
- `.tl-sub-input` 从 20px 高改为随行高（最小 26px），支持多行；
- 预览侧同步显示草稿（可选：通过 `data.commitTimeline` 临时文本，或只在提交后显示，**建议只在提交后**，避免预览闪烁）。

### 4.6 边界情况
| 场景 | 行为 |
|---|---|

## 5. 功能三：三类素材导入

统一入口（编辑模式左侧“素材箱” + 右坞“资产”Tab + 时间线空白右键）：
```
[导入本地]  [本项目] [其他项目] [资产包]     搜索 / 类型 / 排序
```
拖拽统一走 `timeline-dnd` 协议，落到 `computeDrop` 的自动开轨逻辑（与功能一共用）。

### 5.1 本地电脑素材
**现状可用路径（≤25MB）**
- 直接复用 `POST /api/projects/:id/uploads`；
- 前端 `assets.uploadLocalFile()` 已封装（`PropsPanel / Bible / Director3D` 已在用）；
- 需补：导入向导（多选、进度、失败重试）、类型白名单扩展（gif / mov / avi / flac / ogg）、`ffprobe` 读时长/分辨率写资产。

**缺失且必须补的**
1. **时长/分辨率探测**：新增 `POST /api/media/probe`（输入 `fileUrl` 或上传后文件，服务端 `ffprobe -print_format json`）。没有它，时间线片段只能按默认 5s 摆放，用户必须手改。
2. **大文件（>25MB）**：现接口硬拒。三个选项：
   - **A. 分片上传（推荐，纯自建）**：`POST /uploads/init` → `PUT /uploads/:uploadId/chunk/:index` → `POST /uploads/:uploadId/complete`；表 `upload_sessions`；断点续传；合并后 `probe → assets`；配额与清理（24h 未完成自动删）。3–5 天。
   - **B. 浏览器本地转码**：`@ffmpeg/ffmpeg` 已在依赖里，可把大视频压成代理文件（≤25MB）再传。缺点：4K/长片在浏览器里不可行（内存/时间），只能做“短片段代理”。
   - **C. 对象存储直传**：需真实 S3/OSS（当前 `storage.service` 是桩）+ 密钥 + 跨域配置。属**额外服务/权限**。
3. **桌面客户端（Tauri）**：可“引用本地路径”而不用上传（需 fs scope + 后端 path 导入），仅桌面版可用，Web 端不存在此能力。

**安全/边界**
- MIME 白名单 + 内容嗅探（不能只信扩展名）；单文件/单项目配额；病毒扫描不属本期；
- 文件名清洗（已有 `X-Filename` 处理）；路径穿越（已有 `resolveUnderUploads`）；
- 失败清理（已有 unlink）；重复文件用 `contentHash` 判重。

### 5.2 其他任务产生的可复用素材
**能力现状**：`/api/assets?projectId=` 已可按项目取；全局资产页已有“全部项目”。所以“看得到”不是问题，问题是“怎么用、怎么授权、怎么追溯”。

**方案**
- 数据：
  - `assets` 增 `contentHash`、`originProjectId`、`tags jsonb`、`license`；
  - 新表 `asset_refs(id, target_project_id, asset_id, added_by, created_at)`——**零拷贝引用**；
  - 或直接在 `TimelineClip` 增 `sourceAssetId`（推荐，便于导出/溯源/回收）。
- 交互：
  - 面板“其他项目”列表：卡片显示来源项目、创建时间、类型、时长；按钮「引用到本项目」/「拖到时间线」；
  - 引用后出现在本项目资产列表（带“来自 XX 项目”角标），但**不复制文件**；
  - 「复制」需物理复制文件（避免源删除导致断链），默认不做。
- 边界：
  - **权限**：`assets.list` 目前无租户/用户过滤——本地单用户可接受，企业版必须补 `createdBy/tenant` 过滤（否则跨用户泄漏）；
  - 源文件被清理：资产不参与时间线缓存淘汰（只清 `timeline-src/cache`），风险低；仍需存在性检查（HEAD/`/content` 探测）；
  - 外部模型使用：`/uploads` 本地 URL **不能直接喂视频厂商**，必须走 `public-media-library.ensureLibraryUrl`（项目 AGENTS.md 红线）；引用时不做，提交生成前做；
  - 删除引用：删 `asset_refs` 不影响源资产；删源资产需提示“有 N 处引用”。

### 5.3 资产包素材
**现状**：没有资产包概念；没有 zip 依赖（`archiver/jszip/yauzl` 均未安装）。

**自研设计（可行，需 5–7 天）**
- 表：
  - `asset_packs(id, name, description, cover_url, visibility('private'|'project'|'builtin'), tags jsonb, license, created_by, created_at)`
  - `asset_pack_items(id, pack_id, asset_id?, file_url, asset_type, name, meta jsonb, sort_order)`
- 内置包：`shared/asset-packs/*.json` + 迁移 seed（例如：转场音效 10 条、字幕样式 6 套、占位图 20 张）；**无文件上传即可用**。
- 导入包（zip）：`manifest.json`（name/version/license/items[]）+ files；校验：schema、路径穿越、大小上限、MIME、重复；落 `data/uploads/_packs/<packId>/`，登记 items。
- 导出包（zip）：项目素材打包下载（需要 zip 库，建议服务端加 `yauzl`（读）/`archiver`（写）或调用系统 `zip/unzip`——系统依赖不可靠，建议加库）。
- 版权：`license` 必填（内置包标注来源/可商用）；导入时用户确认。
- UI：资产包卡片 → 详情抽屉 → 「加入本项目」/「拖到时间线」；批量导入进度。

**替代方案（若不想做 zip）**：一期只做「内置素材包 + 单文件多选导入」，包=一个 JSON 清单 + 已存在的文件 URL；不做 zip 往返。**成本 2 天，能力 60%**。

5. 权限：企业多用户环境下，看不到其他用户项目资产（需补过滤后验证）。

   - 能力白名单 + “禁止：生成新视频/导出/解锁/删除 locked”
3. 回复末尾围栏：
```
```yimu-timeline
{"baseVersion":12,"ops":[...],"summary":"把第 3 镜剪短到 3 秒，并把字幕提前 0.5 秒"}
```
```
4. 前端解析 → 预校验（存在/锁定/边界/上限/重叠）→ **GateCard diff**（操作/目标/前→后/总时长变化）→ 用户点「应用」。
5. 应用：`POST /api/projects/:id/timeline/agent-ops`（服务端事务）：
   - 校验 `baseVersion`（不一致 → 409 + 要求重算）
   - 用同一份 `shared/timeline-ops.ts` 应用到服务器文档
   - 写入 `agent_edit_ops` 审计表（session/message/ops/resultVersion）
   - 返回新文档 → 前端 `commitTimeline` + 入撤销栈（label = summary）
6. 失败：整批回滚（服务端事务），前端 toast 具体哪条 op 失败。
7. 不做：批量删除 >10 条、跨轨整组重建、花钱操作（重跑镜头）→ 必须走原有确认门/生成按钮。

**能力边界（写进 UI 提示）**
- 能：移动/修剪/分割/删除/改字幕/改样式/变速/音量/建轨/分离合并音频；
- 不能：生成新素材（走生成任务）、导出成片（走导出）、绕过锁定、跨项目操作；
- 不保证：自然语言一次全对 → 一律先出 diff，用户确认。

### 6.5 验收标准（功能四）
1. 点「全功能编辑」→ `/project/:id/edit`，左栏不变，中间无对话框，预览+检查器+时间线可直接操作。
2. 刷新/分享该 URL 回到同一编辑态；`Esc`/返回对话可切回。
3. 浮动 logo 可拖到屏幕任意位置，刷新后位置保留（本项目）；点击打开对话框，Agent 流式回复正常；`⌘J` 可开；红点未读正确。
4. 对话框里说“把第 3 镜剪短到 3 秒” → 出现 diff 卡（前 3.0s → 后 3.0s、总时长 -0.5s），点应用后时间线变化、可撤销、刷新仍在。
5. 说“删掉所有字幕” → 拒绝或要求逐条确认（超过阈值）。
6. `baseVersion` 过期 → 提示重新生成，不覆盖。
7. 锁定的片段/轨道 → Agent 操作被拒并说明原因。
8. 编辑模式下导出仍走同一 EDL；导出前自动 flush。

## 9. 风险与依赖

| 风险 | 影响 | 缓解 |
|---|---|---|
| 保存重建 id（已确认） | 选中/编辑/Agent 全部不稳 | M0 先修，**不修不做后续** |
| 多画面轨无合成 | 用户预期“叠化”落空 | 导出模式开关 + 明确文案；二期合成 |
| 25MB 上限 | 大多数相机素材无法导入 | 分片上传/本地代理/对象存储；先给明确提示与替代 |
| 资产无租户隔离 | 企业版跨用户泄漏 | 企业版前补 `createdBy/tenant` 过滤（安全专项） |
| LLM 无 tool calling | Agent 只能“提案” | 结构化协议 + 确认门 + 纯函数校验；本地命令解析兜底 |
| 409 频繁（多人/多窗口） | 编辑被打断 | 字幕级重基；后续片段级锁/CRDT |
| 浮层遮挡 | 编辑操作被挡 | 可拖/吸附/复位/键盘；默认右下 |
| 性能（多轨+缩略图） | 滚动卡顿 | 已有虚拟化；轨道≤20；缩略图缓存 TTL |

## 10. 总验收（回归红线）

在任何里程碑合并前必须手工回归：
1. **同一数据源**：对话/面板/画布/时间线改动后刷新一致；无第二份状态。
2. **先读后写**：Agent 改前读上下文；提案带 summary。
3. **可追溯**：每次 Agent 应用有审计记录 + diff。
4. **不花钱的操作不偷偷花钱**：Agent 不得触发生成/导出。
5. **不删减既有功能**：右坞 8 Tab、时间线原有操作、导出、经典模式入口全部保留（用户红线）。

功能验收以 §3.8 / §4.8 / §5.5 / §6.5 为准；性能验收：4 轨 × 20 片段滚动 ≥ 50fps（M4 Pro 本机）；保存 P95 < 300ms（本地）。

## 11. GitHub 参考（同类实现）

| 项目 | 可借鉴点 | 与本项目差异 |
|---|---|---|
| [OpenReel Video](https://github.com/Augani/openreel-video)（MIT，React/TS/WebGPU/WebCodecs） | 无限多轨、拖拽、波纹删除、IndexedDB 自动保存、轨道锁定/隐藏 | 纯浏览器本地渲染，导出用 WebCodecs；我们是服务端 ffmpeg + EDL 落库 |
| [@videoflow/react-video-editor](https://www.npmjs.com/package/@videoflow/react-video-editor) | **“把图层拖过最上/最下一行即生成新轨”**（与需求 1 完全同构）；磁吸、缩放、组、异步缩略图 | 基于自有渲染器；我们沿用现有 DOM 轨道 + EDL |
| [DesignCombo react-video-editor](https://github.com/designcombo/react-video-editor)（Remotion） | CapCut 式 UI 布局、时间线交互、服务端渲染导出 | Remotion 渲染模型；我们是 ffmpeg concat/混流 |
| 掘金《纯前端多轨视频编辑器》实践 | 轨道/片段数据结构、拖拽裁剪、实时预览、FFmpeg.wasm 导出 | 无后端持久化与多人；我们以 EDL 为真源 |

**没有现成可抄的部分（需自研）**：
- “EDL 整文档乐观锁 + 片段级稳定标识”的冲突模型；
- “Agent 提案 → diff → 事务应用”的剪辑动作协议（开源编辑器基本没有对话式剪辑）；
- 与短剧生产链（shots/资产/生成任务）耦合的素材引用与资产包。

参考实现只借交互范式，**不引入其渲染/导出内核**（会与现有 ffmpeg 管线冲突）。
