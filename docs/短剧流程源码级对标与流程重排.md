# 短剧流程源码级对标与流程重排

> 起因：用户提问「为什么别人产出的剧前后连贯性好、产出都很完美，我们的不行？」
> 并在追问中点出两个关键：**① 人物与场景的一致性必须先进行生成；② 分镜头也要先生成出来，再依据这些作为参考去生成其他。**

本文是这三家开源项目（火宝 huobao-drama / Toonflow / ArcReel）源码通读后的证据汇总、与我们代码的逐条差距，以及已落地的流程重排。

---

## 一、三家到底怎么保证连贯性

### 1.1 火宝（huobao-drama）

| 机制 | 源码证据 |
|---|---|
| 资产硬门：全部资产有图才解锁视频阶段 | `frontend/app/views/drama/episode.vue:2525` `if (stageId === 'assets') return assetTotalCount.value > 0 && assetReadyCount.value === assetTotalCount.value`；`2456-2457` 处 `assetTotalCount = 角色+场景+道具数`、`assetReadyCount = 各类已出图数` |
| 三段式提示词工作流 | `backend/workspace/prompts/storyboard_breaker.md` → `extractor.md` → `prompt_generator.md` |
| `@角色名` 机械替换成带图号的引用 | `prompt_generator.md` 里 `@角色名` → `@图片3角色名`，顺序固定「场景图 → 角色图 → 道具图」 |
| 参考图数量与顺序被显式约束 | `backend/src/services/generation.ts` / `video-prompts.ts` |

**要点**：火宝并没有更聪明的模型，它是把「资产必须先有图」做成了 UI 与流程的双重硬门，并且提示词里的图号是**机械生成**的，不是让模型猜。

### 1.2 Toonflow（v1.18 workflow skill）

| 机制 | 源码证据 |
|---|---|
| 阶段固定且每阶段有确认关口 | `packages/skills/v118workflow/SKILL.md` 的 14 阶段；资产提取（5）→ 资产出图（6）早于分镜表（10） |
| 清单 ≠ 出图 ≠ 分镜图，三步不许合并 | `references/baseAssets.md`：「本阶段从已确认剧本提取角色、场景和道具…**不自动生成图片**」「清单确认不等同于图片生成授权」；`references/generateAssets.md`；`references/storyboardImages.md` |
| 生成前逐项核对「图片顺序与提示词引用标记一致」 | `references/storyboardImages.md` 的「生成前核查」第 2 条 |
| 场 → 片段 → 镜 三级结构，资产引用挂片段级 | `references/storyboardTable.md` |
| 空间基准九宫格，反打左者右看 | `references/knowledge/shotCraft.md` |
| 参考图必须写真实编号，禁止写「他/她」 | `references/storyboardTable.md` |

**要点**：Toonflow 的连贯性来自**阶段纪律**——每步产物都要被下一步显式引用，任何一步没有产物就走不下去。

### 1.3 ArcReel

| 机制 | 源码证据 |
|---|---|
| 待出图资产非空即阻塞分镜 | `lib/workflow/workflow_state.py` 的 `referenced_assets_without_sheet` |
| 工作流是纯投影（11 步 × 6 态） | `lib/workflow/workflow_plan.py` / `workflow_rules.py` |
| 产物四态 current / stale / missing / blocked | `lib/workflow/workflow_state.py` |
| **「图N」机械编号**：声明行与真正发出的图等长同序 | `lib/prompts/reference_image_numbering.py`：`reference_image_label(pos) = 图{pos+1}`、`reference_images_declaration()`、`mention_replacements()`、`render_reference_mentions()`、`clamp_reference_images()` |
| 上一分镜图作为同段镜像链 | 同上：`PREVIOUS_STORYBOARD_ROLE='previous_storyboard'`，约束句 `PREVIOUS_STORYBOARD_REFERENCE_DESCRIPTION='只参考构图与色调'` |

**要点**：ArcReel 把「编号」这件事做成了一个纯函数模块，注释里写得很直白：*「分镜图与宫格图的参考图对图像模型只是一个图数组，模型能理解的指认方式是『图N』」*。

## 二、我们原来的差距（逐条对照）

| # | 差距 | 我们的代码 | 三家的做法 | 后果 |
|---|---|---|---|---|
| 1 | 物化是正则启发式，不是分镜设计 | `splitScenes()` + `buildShots()`：一句台词一镜 | LLM 按「场→片段→镜」输出分镜表 | 没有景别/机位/轴线概念，剪辑上接不住 |
| 2 | 资产不是前置 | `quickCreate` 扩写关直接 `parse_script`；`ensureSpeakerCharacters` 只建「仅含姓名」的骨架卡 | 资产清单→资产出图→分镜表，顺序固定 | 人物/场景一栏永远是空的 |
| 3 | 状态机跳过 bible_ready | 旧注释明写「跳过 bible_ready」 | bible_ready 是必经里程碑 | 项目从未真正进入资产阶段 |
| 4 | `scenes` 没有图，`generateLocationImage()` 无人调用 | 表有 `locations.reference_image_urls`，但物化时 `locationId` 从不写 | 场景图是空间一致性的唯一锚点 | 同一场地每镜都不一样 |
| 5 | 镜头与人物零连线 | 物化时写死 `characterIds: []`、`scenes.characterIds: []` | 分镜挂资产引用 | 首帧取不到任何人物参考图 |
| 6 | 参考图编号是**字符串字面量** | `` `[图N] 角色：${c.name} —— ${lock}` `` —— 模型看到的是「图」「N」三个字符 | 编号 = 数组位置，机械渲染 | 多图时无法指认，三张图全像一个人 |
| 7 | 镜头之间没有链 | 同场相邻镜各生成各的 | `previous_storyboard` + 「只参考构图与色调」 | 相邻镜跳轴、光位跳变 |
| 8 | 场景图不进参考图数组 | `autoRefs` 只读 `shots.referenceImageUrls` + 人物 + 道具 | 场景图是参考图的第一梯队 | 场景一致性无从保障 |
| 9 | 空集合判定为「通过」 | `items.every(ready)` 对空数组返回 `true` | 资产数为 0 时硬门不通过 | 「一个人都没有」也敢出片 |
| 10 | 分镜表质量无门 | `boards` 只要 JSON 能解析就落库 | 分镜图验收逐项核对 | 空分镜落库后污染下游 |

## 三、重排后的目标流程（S0–S8）

```
S0 script        剧本（技能/粘贴/扩写）
S1 asset_prep    资产前置：补齐圣经清单 → 排定妆图（人物主图+四视角 / 场景参考图 / 关键道具设定图）
S2 bible_ready   资产就绪硬门（readyCount === total 且 total > 0）
S3 boards        分镜表（LLM，按场→镜；质量门不过则降级）
S4 storyboard    分镜物化 + **绑定资产**（scenes.location_id / scenes.character_ids / shots.character_ids）
S5 frames        首帧：**参考图真实编号** + 场景图 + 上一镜成帧，提示词分「不可变/可变」两段
S6 video         视频（等本镜首帧成功；失败不裸跑）
S7 audio/edit    配音 → 剪辑
S8 qc            质检 → 成片
```

关键约束：

- **S1 必须在 S3 之前**，且 S3 的任务带 `blockedReason='waiting_assets'`，资产不齐不认领；
- **S4 必须把资产写进分镜**，否则 S5 无从取参考图；
- **S5 的图号必须由编排层机械渲染**，且声明行与真正发出去的图等长同序；
- 降级必须显式：结构性失败（等不到图）重排两次后放行，并在 `projects.metadata.assetGate` 写 `degraded: true`，不许假装资产齐全。

## 五、验收口径

1. **资产门**：新建项目跑完后，`characters.identity_kit.portraitUrl` 与 `locations.reference_image_urls` 必须非空，否则项目不得进入 `storyboard_ready`；
2. **连线**：`select count(*) from scenes where location_id is null` 应为 0（单场景剧本允许兜底绑定）；
3. **编号**：任一镜头首帧任务日志里必须出现「图1、图2为…」而非「图N」；
4. **不撒谎**：资产等不到图时，`projects.metadata.assetGate.degraded = true`，且项目仍能走完，不许静默降级；
5. **不跳级**：`projects.status` 历史里不允许出现 `planning → storyboard_ready` 的直接跳转。

## 六、下一步（P1，尚未做）

1. **片段（segment）概念**：Toonflow 的「场 → 片段（≤15s, 2-4 镜）→ 镜」三级，我们现在只有场 → 镜；
2. **video_prompt 按 3 秒分段**（火宝做法）：0-3s / 3-6s 每段写画面 + 台词，替代现在一句话给整镜；
3. **同段镜像链**：ArcReel 的 `previous_storyboard` 已接入首帧，视频阶段还应带上一镜末帧做续接；
4. **空间基准九宫格**：把「左/中/右 × 前/中/后 + 反打规则」写进分镜表提示词，解决跳轴；
5. **道具状态变体**在提示词层的注入（`stateVariants` 已建表，尚未进入首帧上下文）。
