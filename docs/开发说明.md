```

                    ┌───────────────────────────┼─────────────────────────┐

           直接伺服 dist/client       转发后端 NestJS           转发后端 NestJS
                    │                           │                         │
                    └───────────────────────────┼─────────────────────────┘
                                                ▼
                                     后端 NestJS :3000
                                        │
                                        ▼

```

### 3.1 为什么需要本地网关（而不是直连后端）
云端由平台网关承担三件事，本地必须由环境层模拟：
1. **伺服静态资源**：后端 `ViewController @Get(['/', '*'])` 会劫持一切请求渲染 HTML，静态资源必须由网关伺服（否则浏览器报 MIME 错误）
2. **注入用户身份**：云端 LarkGW 注入 `x-larkgw-suda-webuser` 请求头，后端据此建立 `req.userContext`；本地由网关注入
3. **数据补全**：云端存在「前端已调、后端未实现」的 dashboard 接口（recent-projects / activity / usage-trend），本地网关直连 PostgreSQL 补齐（不改云端源码）

### 3.2 平台 SDK 关键行为（已从 node_modules 源码确认）
| 机制 | 行为 | 本地处理 |
|---|---|---|
| 数据库连接 | 读 `SUDA_DATABASE_URL`，`?schema=yimu` 决定角色前缀 | 连接串 `postgres://localhost:5432/yimu?schema=yimu` |
| 数据层角色 | 登录用户执行 `SET LOCAL ROLE 'authenticated_<schema>'` | 本地创建角色 `authenticated_yimu` 等并授权 |
| 用户上下文 | header `x-larkgw-suda-webuser`（URI 编码 JSON）→ `req.userContext` | 网关注入 |
| CSRF | cookie `suda-csrf-token` === header `x-suda-csrf-token` 即放行 | 后端下发随机 token，前端自动带同值 header，网关兜底 |
| 前端路由 basename | `window.__BASENAME__`（后端渲染时注入 `/app/yimu`） | **必须通过 `/app/yimu/` 前缀访问**，否则 Router 无法匹配 URL 渲染空白 |

### 3.3 为什么必须用 /app/yimu/ 前缀访问
前端 `BrowserRouter basename = /app/yimu`（与云端一致）。React Router 要求当前 URL 必须以 basename 开头才能匹配路由。云端应用部署在 `/app/yimu` 路径下，因此本地也必须访问 `http://localhost:5173/app/yimu/`。访问根路径 `/` 会因 URL 不匹配 basename 而白屏（这是 Router 的正常行为，非 bug）。

## 六、本地 vs 云端的差异说明

用户要求「本地与云端一模一样、零修改」。实现上：
- **云端业务源码（client/ + server/ + shared/）**：与云端**逐字一致**，未做任何修改
- **环境基础设施（scripts/gateway.js、scripts/db-init.sql、scripts/start.sh）**：本地新增，负责模拟平台网关/数据层行为，不属于业务代码
- **唯一增强**：本地网关补齐了云端因前后端不一致而缺失的接口（项目详情 / 按场景查镜头 / dashboard 数据），让页面真实可用；云端同样缺失（线上同样 404），本地是「修复版」，UI 与云端完全一致

### 6.2 本地网关数据补全（scripts/gateway.js 新增）

云端前后端不一致、本地在环境层补齐的接口：

| 接口 | 缺失原因 | 补全方式 |
|---|---|---|
| `GET /api/projects/:id` | 后端缺 `@Get(':id')`，前端 getProject 调用 404 | 网关直连 projects 表返回完整 Project |
| `GET /api/projects/:id/storyboard/scenes/:sceneId/shots` | 后端只有全局 shots 路由，前端 listShots 走嵌套路由 404 | 网关按 project+scene 过滤返回镜头 |

> 这些接口在云端同样 404（线上也有该 bug），本地补全是让功能可用，不改变 UI 与配色。

## 七、后续开发指引

### 新增页面
1. 在 `client/src/pages/` 下新建目录与组件
2. 在 `client/src/app.tsx` 的 `<Routes>` 中注册路由
3. 页面 API 调用在 `client/src/api/` 下封装

1. 在 `server/modules/` 下新建模块（controller + service + module）

3. 表结构变更在 `server/database/schema.ts`，同步更新 `scripts/db-init.sql`

在「设置」页配置 Provider 即可，后端 `model_providers` 表持久化。生成逻辑在 `server/modules/generation/`。

### 自定义 AI 能力
各能力调用点：
- 文本生成：`server/modules/generation/`（剧本/文案）
- 图片生成：分镜/角色/场景图

- TTS：配音
统一走 Provider 配置（火山方舟 / 中转站 / 自定义）。

## 八、常见问题排查

| 现象 | 原因 | 解决 |
|---|---|---|
| 首页白屏 | 未用 `/app/yimu/` 前缀访问 | 访问 `http://localhost:5173/app/yimu/` |
| API 403 | CSRF header 缺失 | 通过网关访问（网关自动补齐）；清浏览器 cookie 后重进 |
| `role "authenticated_" does not exist` | 连接串缺 `?schema=yimu` | 确保 `SUDA_DATABASE_URL` 带 `?schema=yimu`，角色已创建 |
| 静态资源 MIME 报错 | 直连后端（后端把静态当 HTML）| 必须经网关 5173 访问 |
| 端口被占用 | 服务已在运行或旧进程残留 | `./scripts/stop.sh` 后重启 |

### 9.2 关键实现要点（供后续开发阅读）
1. **节点即工具箱（Pavo 核心交互）**：`pavoTypes.ts` 的 `NODE_META_V2[kind].tools` 定义每种节点的专属工具；点击节点 → `toolsNodeId` 置位 → `NodeToolsPanel` 按节点类型渲染工具按钮 → 选中工具后出现提示词输入 + 「@ 引用资产」（referable = isAsset 或 character/scene/image/asset/text/script 节点）+ 生成按钮。
2. **分支生成 + 版本保留**：`handleInvoke` 调 `runPavoTool(kind, toolId, prompt)` 产出**新节点数组**（绝不覆盖源节点），从源节点自动拉边（`type:'yimuEdge'`，label 记生成说明）；旧节点保留 → 天然版本对比；「局部重生成」工具即产出带「v2 新分支」的并列节点。
3. **一键铺开（Pavo Harness）**：顶部输入故事 → `autoHarness` 自动拆解角色资产（2）+ 场景资产（3）节点，带 `isAsset:true` + 资产徽标，供后续 @ 引用保持一致性。
4. **3D 导演台**：模态面板；SVG 俯视摆位（`moveItem` 按 clientX/Y 归一化 0-100）；导出时把角色/相机位置画成 SVG dataURI → 作为 image 节点落回画布。
5. **双击加节点**：`document.addEventListener('dblclick', onDbl, true)` 捕获监听，命中 `.react-flow__pane` 且未命中 `[data-yimu-panel]` / `.react-flow__node` 才弹出 11 种节点面板。
6. **集切换 / 持久化**：`storageKey = yimu-pavo-v1-{projectId}-ep{episode}`；加载 useEffect 依赖 `[projectId, episode]`；`persist` 用 `keyRef.current`（避免切集时序写脏数据）；**加载时统一 `generating:false`**（避免旧数据残留"生成中"态）。
7. **@ 引用（小云雀融合）**：节点工具面板与对话助手共用 `referable`（资产节点列表）；对话输入框 @ 唤起列表、点选插入 `@标题 ` 到输入。
8. **对话助手（小云雀融合）**：多会话标签页（`sessions` 数组 + activeId）、4 Agent、创意助手（热点/爆点/选题/方案 → 映射为演示指令）、流式打字机、落地为画布节点。
9. **视觉**：`PAVO_C` 青绿令牌（bg #F6F7F7 / primary #1FA97E / primarySoft #E7F6F0），全面替换紫色主题；节点/面板浅白底 + 淡青边框 + 圆角 12-14。

### 10.7 三通道 API 对接说明（已完成）
三种对接方式均已实现，`pavo3Store.ts` 的 `apiConfig`（三通道配置结构：火山方舟 / OpenAI 兼容中转站 / 自定义 API）与后端 `server/modules/pavo3/` 代理打通，调用链如下：
1. **火山方舟**：`https://ark.cn-beijing.volces.com/api/v3/chat/completions`（OpenAI 兼容），模型用方舟推理接入点 ID（endpoint id）或模型名；
2. **OpenAI 兼容中转站**：用户自备 baseURL + API Key，直接走 `/v1/chat/completions` 与 `/v1/images/generations`；
3. **自定义 API**：用户填写 baseURL / key / 模型名 / 图片接口路径，前端透传。
- 发送点在 store 动作内统一收敛：文本走 chat/completions，图片走 images/generations（或中转站图片接口），视频/音频按厂商能力表映射；生成中节点状态置「执行中」+ 进度，完成后置「已完成」。
