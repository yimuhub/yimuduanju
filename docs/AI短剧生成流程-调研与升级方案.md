# AI 短剧生成流程：行业调研与本项目升级方案

> 2026-11-11。起因：《雨夜末班车》一个剧本产出「两种风格」内容、
> 片头变成一张公交车海报、16:9 项目出方图与竖屏视频。
> 本文先给现状结论，再对照 GitHub 上的开源管线，给出分阶段升级方案。

---

## 一、问题定性（已修复部分）

| 现象 | 真正原因 | 状态 |
|---|---|---|
| 一个剧本像出了两套内容 | 每场固定「1 全景 + N 台词特写」，全景 prompt 是含台词的整场摘要，特写再说一遍同一句台词 | 已修 |
| 片头是一条公交车海报 | `剧名：雨夜末班车` 被判成第 1 场，物化出「剧名特写」镜，还把「末班车」画成公交 | 已修 |
| 同一角色每镜换脸 | `characters` 为空、`character_ids` 恒空，生图没有任何参考图 | 已修（自动建骨架人物并绑定镜头） |
| 全景是夜景、特写是白天 | `styleBible / worldView / artStyle` 从未进入提示词 | 已修（生成时统一注入画风块） |
| 16:9 项目出方图 | 图片任务从不传 `size`，网关默认 `1024x1024` | 已修（按项目画幅映射，实测 1312×736） |
| 16:9 项目出竖屏视频 | Agnes 通道把 `aspect_ratio: '9:16'` 写死 | 已修（跟随项目画幅，日志可见 `aspect=16:9`） |
| 参数错误重试 3 次 | 400/422 也走重试预算 | 已修（参数类 4xx 立即失败） |

### 仍未解决的关键缺口

1. **首帧没有真正进入视频模型。** 首帧是本地 `/uploads/...`，网关判断「非公网 URL」后跳过
   `first_frame`，实际全部退化成 `mode=text` 文生视频。所以视频内容与首帧构图对不上，
   这是「感觉不对」里最隐蔽的一条。
2. **剧本 → 分镜仍走启发式。** 项目里有 LLM 分镜能力
   （`POST /api/projects/:id/storyboard/script-to-boards` → `runBoards`），但创建流程与
   前端都没有入口，实际永远是 `parse_script` 按行切。
3. **项目时长与成片时长不对齐。** 60s 的设定可以物化出 83s 的镜头表，没有任何提示或校正。
4. **画幅回退会静默降级。** 供应商不支持目标尺寸时回退 1024×1024，只在日志里留一行 warn。

## 二、GitHub 调研：别人怎么做 AI 短剧 / 漫剧

调研对象（均为源码可见的自托管管线）：

| 项目 | 定位 | 关键做法 |
|---|---|---|
| `dramaclaw/dramaclaw` | 工业化短剧生产线 + 无限画布双轨 | 故事图谱先行；资产库（角色/场景/道具/声线）跨集复用；**线稿草图先定构图再上色**；每步独立任务、可断点续跑 |
| `Forget-C/Jellyfish` | 端到端短剧工作台 | 剧本拆镜 + 结构化提取（角色/场景/道具/服装/对白）；**镜头就绪制**：拆镜 → 准备 → 候选确认 → ready → 生成；「已准备」与「生成中」严格区分 |
| `xuanyustudio/LocalMiniDrama` | 本地优先短剧/漫剧 | 故事 → 剧本 → 角色 → 场景 → 道具 → 分镜 → 图/视频 → 合成，一键流水线；SQLite + 本地文件 |
| `uu889/uu889-drama` | 小说 → 短剧全自动 | 4 个 Agent：script_rewriter / extractor / storyboard_breaker / prompt_generator；分镜提示词用 `@角色名` 映射参考图 |
| `MemeCalculate/moyin-creator` | 桌面端生产工具 | 「角色圣经」六层身份锚点；智能剧本解析出场景/分镜/对白/角色/情绪/镜头语言；首帧图网格拼接（N×N） |
| `NINKCH/dsh-infinite_canvas` | 画布式创作 | 项目级设定集（角色/场景/道具卡）；`@名称` 自动携带设定与参考资产；分镜后一致性检查；尾帧串联 |

### 五条共性结论

1. **先定 beat，再定镜。** 结构是 剧本 → 场 → beat（一句台词/一个动作）→ 镜；一镜只承载一个 beat。
   没有任何一个成熟项目会把「整场摘要」和「其中一句台词」各拍一遍。
2. **资产库是硬前置，不是可选项。** 角色/场景/道具/服装/声线统一登记，镜头只引用 ID；
   `@角色名` 这类引用语法会把设定文本 + 参考图一起带进提示词。
3. **镜头就绪制。** 拆完镜不会直接开跑，先检查「有没有人物形象 / 场景参考 / 道具参考 / 提示词」，
   就绪才允许消耗算力。Jellyfish 明确把「prepared」和「generating」分开。
4. **先构图后生成。** DramaClaw 用线稿定构图再生成；Moyin 用首帧网格批量出图再选优。
   本质都是「便宜的步骤多试，贵的步骤少错」。
5. **时长由内容决定，但整体要收口。** 每镜时长按台词字数算，同时全片总时长要与设定对齐，
   否则时间线、字幕、配乐、导出全错位。

### 与本项目的差距

| 能力 | 行业基线 | 我们 | 差距 |
|---|---|---|---|
| beat 粒度分镜 | 一镜一 beat | 已对齐（本次修复） | 无 |
| 人物/场景/道具资产库 | 镜头级引用 + 参考图 | 有表、有 UI，但默认不自动建 | 中 |
| 镜头就绪门 | 未就绪不允许生成 | 有 GateCard 提示，但可绕过 | 中 |
| 首帧参与图生视频 | 必需 | **未生效（全走文生）** | **高** |
| 线稿/首帧选优 | 常见 | 无 | 中 |
| 时长收口 | 对齐设定 | 不对齐 | 中 |
| LLM 分镜入口 | 默认路径 | 有接口无入口 | 高 |

## 三、升级方案

### P0（本轮必须收口，否则「两种风格」还会复发）

**P0-1 首帧真正进入视频生成**
- 加 `PUBLIC_BASE_URL` / 对象存储上传二选一：有公网基址就重写 `/uploads` 为绝对 URL；
  否则走「上传到供应商文件接口」或 data-URI 试探。
- 网关侧：`first_frame` 必须是供应商可拉取的 URL；拿不到时**明确告警并在镜头卡上标注
  「本镜为文生视频，未使用首帧」**，不要静默降级。
- 验收：视频任务日志出现 `mode=keyframe`，且视频首帧与设定图同构图。

**P0-2 时长收口**
- 物化后计算 `sum(duration)`，与 `projects.durationSeconds` 偏差 > 20% 时：
  优先按比例微调（不越过 4s 下限），仍超差则把实际时长写回项目并提示「剧本内容需要 83s」。
- 验收：60s 项目不再无声产出 100s+ 镜头表。

**P0-3 画幅不再静默降级**
- 供应商拒绝目标尺寸时，任务上标 `sizeFallback: true`，在质检页与导出页提示；
  提供项目级「画幅必须严格」开关。

### P1（下一轮，决定"能不能做长剧"）

**P1-1 LLM 分镜接入主流程**
- 创建/确认剧本时按内容模式选路：完整剧本 + drama 模式 → `boards`（LLM）；
  一句话扩写 → 先 `script` 再 `boards`；无法调模型时回落 `parse_script`。
- 前端补「AI 分镜」按钮（`replaceExisting` 可覆盖），并保留人工微调。

**P1-2 资产库硬前置**
- 分镜就绪判定统一为：人物有主图 + 四视图、场景有参考图、道具参考齐、提示词非空。
- 未就绪时「批量生成」直接拦下，给出「缺什么、去哪个页面补」的清单，
  而不是允许生成后靠人眼发现穿脸。

**P1-3 首帧候选与选优**
- 每镜生成 2–4 张首帧候选，人工选一张定稿再进视频（Moyin 的 N×N 思路）。
- 成本可控：候选阶段用低分辨率/低价模型，定稿再走高质量通道。

### P2（体验与产能）

- **P2-1 场景/道具状态变体**：同一场景的白天/夜晚/破损作为变体，不新建场景。
- **P2-2 尾帧串联**：相邻镜头用尾帧接首帧，减少跳变（`dsh-infinite_canvas` 做法）。
- **P2-3 剪辑决策与生产台账分离**：`timeline_clips` 只存剪辑决策，`shots` 存生产台账，已具备。
- **P2-4 任务中心的"就绪/生成中/失败"三态可视化**，减少"到底卡在哪"的猜测。


## 五、验收口径

1. 任意剧本物化后：镜数 = 台词条数（无台词场为 1），同一句台词只出现在一镜。
2. 片头元信息（剧名/类型/时长/人物表）不产生镜头。
3. 每镜 `character_ids` 非空（有台词时），且人物卡存在。
4. 首帧比例与项目 `aspect_ratio` 一致（误差 ≤ 5%）。
5. 视频任务若未使用首帧，镜头卡必须有显式标注。
6. `sum(duration)` 与项目设定偏差 ≤ 20%，或已写回真实时长。
