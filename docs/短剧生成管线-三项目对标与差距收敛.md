# 短剧生成管线 · 三项目对标与差距收敛

> 调研对象：火宝短剧（chatfire-AI/huobao-drama）、Toonflow（HBAI-Ltd/Toonflow-app）、ArcReel（ArcReel/ArcReel）
> 本轮结论以「可程序化的确定性规则」为准，不抄它们的「靠提示词自觉」。
> 落地代码见文末「已落地」一节，均已通过 `tsc` 与 97 条单测。

---

## 一、三家的管线是怎么回事

### 1. 火宝短剧 · 一句话到成片（约 13k star，TypeScript 全栈）

链路：`小说/一句话 → 剧本改写 → 角色场景提取 → 分镜拆解 → 宫格图 → 图生视频 + TTS + FFmpeg 合成`

五个 Mastra Agent 分工：

| Agent | 职责 | 关键约束 |
|---|---|---|
| `script_rewriter` | 改写成格式化剧本 | 场头 `## S01 \| 内景·地点 \| 时间`；台词 `角色：（状态）台词`；每场 30–60s；**故意不写镜头语言** |
| `extractor` | 抽角色/场景并去重 | 角色按姓名精确匹配后**更新**而非新建；场景按 `地点+时间` 去重 |
| `storyboard_breaker` | 拆分镜 | 每镜必须有 `shot_type / angle / movement / action / dialogue / image_prompt / video_prompt`；`scene_id` 与 `character_ids` **必须来自本集上下文**（校验后才落库） |
| `voice_assigner` | 分配音色 | 按性别/年龄/性格标签 |
| `grid_prompt_generator` | 出英文提示词 | 角色图 / 场景图 / **宫格图** 三模式 |

三个值得抄的工程点：

1. **`video_prompt` 按 3 秒分段写**：`0-3秒：咖啡厅，近景，小明低头看手机…`。视频模型对「时间轴上的动作」比「一段描述」听话得多。
2. **本地图片 → 压缩 Data URL**（`normalizeReferenceImages`）：`/static/...` 读盘后用 sharp 缩到 768、质量 68 转 base64。**供应商不需要能访问你的机器**。这是它能稳跑图生视频的根本原因。
3. **宫格图先确认再出视频**：一张多格图统一画风，切分后分别送视频，省钱且同段更一致。帧类型分 首帧/尾帧/分镜板。
4. 参考模式四档：`none / single / first_last / multiple(2-6)`。参数错误 4xx 不重试。

短板：分镜字段里没有「光线/氛围/环境音」的独立位；`negative_prompt` 直接按通道过滤，没有风险分级。

### 2. Toonflow · 卖的是规则不是软件（约 16k star）

软件层（无限画布 + Agent + 插件市场）其实模型都能替；真正值钱的是 `packages/skills` 里约 90KB 的**导演规则文档**。核心几条：

- **每段必须把站位/光线/道具在哪只手从头写一遍**，禁止「同上」「延续上一段」。视频模型每段都是从零开始，省略=让它猜。
- **接缝三选一**：上一段末镜与下一段首镜，至少满足一条 → ①拍的主体不同 ②景别差两档以上 ③角度差 90 度以上。
- **没拍到不等于不存在**：手里拿着笔没写放下，下一镜笔不能凭空消失。
- **文字分两类**：字幕/标题绝不让视频模型生成；画面内既有文字写「保持参考图原样，不新增不改写」。
- **高风险清单**：3 人以上同时大幅动作、双手操作小物件+复杂运镜、镜子玻璃水面、包装小字特写+快速移动。遇到先简化运镜，再让手部接触完整入画，最后才拆镜。
- **不要全片堆几十个「禁止」词**，只对真正有风险的那段写一两条。
- **剧情保真锁（A0.1）**：只导演不编剧。把剧本拆成最小事件 E01/E02…，提示词里凡是改变人物/道具/位置的句子必须能对上编号；对不上就是 AI 加的戏，删掉。
- **时长**：字数÷语速（急促 4 字/秒、正常 3、悲伤 2）+ 每处停顿 0.3–0.5s + 首尾各约 1s。24 字 ≈ 8–10s，不能靠加快语速硬塞。
- **衍生图要累积**：第 2 场袖子破、第 4 场徽章掉 → 第 4 场的图必须同时是「破袖子+没徽章」，不能只去掉徽章把袖子复原。

它自己承认的短板：这些规则全靠模型自觉读、自觉遵守，三份文档之间还有互相矛盾的条目。**把它从「文字要求」改成「程序检查」，正是我们可以拉开差距的地方。**

### 3. ArcReel · 把生产做成可审核流水线（约 6k star，Python/FastAPI）

七个工位：`内容分析 → 角色/场景/道具资产 → 分集与结构化剧本 → 分镜图（含多宫格）→ 视频片段+旁白 → 成片 / 剪映草稿`

关键设计：

- **三种创作类型决定拆分逻辑**：剧情演绎 / 旁白解说 / 广告短片（广告按总时长+卖点规划，每镜带口播）。
- **两种生成方式**：分镜图生视频 / 参考生视频（创建后不可改）。
- **分镜字段拆得极细**：Image Prompt 组（提示词/参考图/角色）与 Video Prompt 组（提示词/首帧/时长/画幅），光质、氛围、景别、环境音效都是独立字段。
- **产物四态**：当前 / 过期 / 缺失 / 阻塞。默认批量只补「缺失」，改过提示词后必须显式选择重生成；阻塞项不会被当成缺失自动重做。这是防「改一次全线返工」的核心。
- **幂等 + 断点续跑**：任务落库、重启恢复、视频任务续跑，避免同一分镜重复扣费。
- **剪映草稿导出**：AI 只做粗剪，把控制权交回剪辑师。这个「出口」设计比多一个转场特效更值钱。

## 二、我们原来的真实差距（按严重度）

| # | 差距 | 后果 | 严重度 |
|---|---|---|---|
| 1 | 参考图与首帧是本地 `/uploads/...` **相对路径**，被原样发给供应商 | 人物主图/四视图/道具图实际从未送达 → 一致性只剩文字在撑；首帧永远进不了 keyframe 模式 → 所有视频退化成文生视频 | **P0** |
| 2 | 相邻镜无接缝约束，逐镜独立生成后直接拼 | 同一角色连说两句时 特写接特写，成片「跳一下」 | P1 |
| 3 | 每镜 prompt 没有站位，只有「在场景中说话」 | 模型自己猜左右，正反打不成立 | P1 |
| 4 | 全片挂同一串负面词 | 负面词越多画面越糊，风险场景又没被针对性约束 | P1 |
| 5 | 单镜时长一律按 4 字/秒估 | 悲伤/哽咽台词系统性偏短，配音被裁或加速 | P1 |
| 6 | 单镜时长按内容算但**没有总时长预算** | 60s 项目物化出 83s，和设定对不上 | P1 |
| 7 | 分镜缺 光线/氛围/环境音 独立字段 | 无法逐镜调，只能整段重写 | P2 |
| 8 | 无「产物四态」，改提示词后不知道哪些图过期 | 容易拿旧图当新图，返工放大 | P2 |
| 9 | 无多宫格分镜、无剪映草稿 | 试错成本高、交付不可继续编辑 | P2 |

## 三、这轮已落地（代码级）

### 1. 参考图/首帧真正送达（P0）

新增 `server/modules/generation/media-input.ts`：

- `http(s)` / `data:` 原样透传；`/uploads/...` 读盘转 **data URL**；其它形态返回 `undefined`（宁可当没有参考图，也不发坏地址）。
- 超过 900KB 用 ffmpeg 压成 JPEG（长边 1280、q4）。实测 **1.09MB PNG → 81KB，93ms**。
- LRU 48 条缓存：同一张人物主图复用于几十个镜头时只读一次盘。

接入点：

- `generateImage`：参考图先规范化；**带图请求被拒时自动去掉参考图重试一次**（降级为文生图，不让整镜失败）。
- `createAgnesVideo`：首帧/尾帧先规范化，`isPublic()` 只用于参考视频；**keyframe 被拒时自动退回 text 模式重提**。
- 火山方舟 / OpenAI 兼容视频通道同样改用规范化后的首帧。

> 这条一修，人物四视图、道具参考图、首帧才第一次真正进入模型。

### 2. 接缝三选一 · 物化时自动修复（P1）

新增 `shared/shot-continuity.ts`：`checkSeam` / `sizeForSeam` / `repairSeams`。
景别排序 7 档，判定 `主体不同 || 景别差≥2 档 || 角度差≥90°`。
物化时逐镜修复：同主体且景别过近 → 自动把景别拉开两档（上一镜已很近就退远，避免「特写接大特写」越拍越糊），**跨场也延续**上一场末镜的状态。

同时在 `shared/qc-rules.ts` 补 `ruleSeamBreak`，对既有项目与手工改镜做兜底巡检。

实测：林晚连说三句 → `中景 / 特写 / 中景`，接缝全部满足。

### 3. 站位每镜重写（P1）

`shared/negative-prompt.ts` 的 `composeBlocking`：按确定性规则给站位，正反打左右交替，全景给环境主导，**永不出现「同上」**。
分镜 prompt 现在是四段：`【场景】/【画面】/【站位】/【台词】`。

实测产物：

```
【场景】第2场 车厢内 夜
【画面】中景，固定机位；林晚的表演与反应，视线随台词对象移动
【站位】林晚居画面左侧面向右，陈默虚化在画面右侧背景
【台词】林晚：你说话啊。
```

### 4. 风险自适应负面词（P1）

固定技术底线 3 条（字幕/文字水印/logo标识）+ 按本镜风险最多追加 2 条：

| 风险特征 | 追加负面词 |
|---|---|
| 3 人以上同框 | 多余人物、人物面部重复 |
| 镜/玻璃/窗/水面/倒影/屏幕 | 镜像重影、多余肢体 |
| 手部操作小物件 + 中近景/特写 | 手指畸形、道具穿模 |
| 复杂运镜（环绕/跟拍/升降） | 画面撕裂、人物形变 |

总数封顶 8 条。分镜落库时写进 `shots.negative_prompt`，生图时优先用库里的值，老项目现值兜底。

### 5. 时长：语速分档 + 停顿 + 总预算（P1）

`shared/shot-duration.ts`：

- `inferSpeechPace`：急促 4 / 正常 3 / 悲伤 2 字每秒（按情绪词与台词文本判定）。
- `estimateDialogueSeconds`：字数÷语速 + 标点停顿 0.35s×最多 6 处 + 首尾 1.2s；自动剔除「林晚：」这类角色前缀。
- `minimumReadableSeconds`：台词念得完的硬下限。
- `fitTotalBudget`：超预算时**只砍余量（景别/运镜加成），不砍台词**；按各镜余量等比例回收；余量砍光仍超就如实报 `overflow`，让用户决定删台词还是加时长，**绝不静默截断对白**。

物化改成两遍：先规划全片镜头（含跨场接缝），再算总预算，最后才写库。

### 6. 顺手修掉一个会导致整机退出的隐患（P0）

`job-worker` 的 Redis 客户端原来把 `retryStrategy` 设成 `() => null`，等于**永不重连**：任何一次瞬断都触发 `'end'` → 降级 → 连带把 Node 进程带走，后端每 30–90 秒自杀一次、前端 502。

改为：短连接探活（3s 快速失败）→ 正式连接用**默认重连策略**（保留 BullMQ 必需的 `maxRetriesPerRequest: null`）→ 给 Worker/Queue 补 `'error'` 监听器 → 降级时只置模式标志，不在事件回调里 close/disconnect 死连接。

## 四、还没做（按建议顺序）

1. **多宫格分镜**（火宝/ArcReel 都靠它省钱）：一段先出一张 2×2/3×3 宫格统一画风，切分后分别送视频。省钱 + 同段一致，是投入产出比最高的下一步。
2. **`video_prompt` 按 3 秒分段**：现在视频提示词是一段描述，改成时间轴分段能明显改善「动作不听指挥」。
3. **产物四态（当前/过期/缺失/阻塞）**：改提示词或旁白后标记过期，批量只补缺失。现在改完只能靠人记。
4. **分镜补 光线/氛围/环境音 独立字段**：对齐 ArcReel，让用户能逐镜调而不是整段重写。
5. **剧情保真锁 E01 编号**：把「只导演不编剧」做成程序校验——提示词里改变人物/道具/位置的句子必须能对上事件编号。
6. **剪映草稿导出**：交付物可继续编辑，比多一个转场特效更有价值。
7. **衍生图累积**（换装/受伤/淋湿的状态链），避免「去掉徽章却把破袖子复原」。
