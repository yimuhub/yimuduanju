## 一、各项目源码级发现

### 1. huobao-drama（火宝）——「单集工作台 + 字段级乐观更新」范本

#### ① 分镜编辑页长什么样

- 页面文件：`frontend/app/views/drama/episode.vue`（6239 行，Nuxt 单文件）。整页是**全屏工作台**，不是右侧面板。
- 布局三层：
  - 左侧**步骤导航**：script raw → script rewrite → assets → storyboard/videos。
    - 每个 section 有 `sectionState()` 派生 done/active 状态。
    - 底部有四段主流程进度跑马灯（`sidebar-progress`），分段可点击跳转（`goMainStage`）。
    - 这是「流程即导航」的做法：用户永远知道自己在管线的哪一步。
  - 主区按 `panel`（script/production）与 `prodTab`（assets/videos）切换：
    - 脚本区是全屏高 textarea（`fill-textarea`），原文与改写剧本两步分开编辑。
    - 视频生产区是**三栏工作台**（`video-task-workbench`，CSS 变量 `--vleft/--vright`，可拖拽调宽，见 `startVideoColDrag`）。
- 三栏细节：
  - 左栏 `video-task-list`：分镜任务行。
    - 缩略图 `poster` + `preload="none"`（不预载视频）。
    - `#01` 序号、状态点（pending/done/failed）、时长、地点摘要。
    - 顶部 pending/done/failed 计数按钮即过滤器（`toggleVideoFilter`）。
    - 失败行内含「复制诊断 copyVideoDiagnostics」「重新生成 forceNew」「失败批量恢复 retryFailedVideos」。
  - 中栏 `video-main-col`（**检查器**）：
    - `description`（7 行 textarea）、`atmosphere`（2 行）：`:value` + `@blur="updateField(selectedSb, 'description', $event.target.value)"` 失焦保存。
    - `video_prompt`：`MentionTextarea`（支持 @ 提及资产名）14 行，`@commit` 保存。
    - 引用资产区 `storyboard-ref-list`：按 `REF_KINDS`（角色/场景/道具）分组，点击 `toggleShotBind(selectedSb, asset)` 绑定/解绑；资产图未就绪时显示「未就绪」+「去生成」跳转（`prodTab = 'assets'`）。
  - 右栏 `video-task-inspector`：播放器 + 该镜任务历史。
- 每镜可编辑字段（对应 `backend/src/db/schema.ts` 的 `storyboards` 表，L110-140）：
  - 文本类：`title / location / time / shotType / angle / movement / result / atmosphere / imagePrompt / videoPrompt / bgmPrompt / soundEffect / description / duration`。
  - 产物类：`composedImage / firstFrameImage / lastFrameImage / referenceImages / videoUrl / subtitleUrl / composedVideoUrl`。
  - 关系类：`storyboard_characters`、`storyboard_props` 两张多对多绑定表（复合主键）。
- 核心函数 `updateField()`（episode.vue L2616）：
  - 先改本地状态（snake/camel 双写），再 `storyboardAPI.update(sb.id, { [field]: value })`。
  - **单字段乐观 PATCH**，失败才 toast 回滚提示。
  - 这是「字段级精修」的范式：不做整对象 PUT，不弹保存对话框。
- 参考图管理链路：
  - 资产先行：`characters.imageUrl/referenceImages/seedValue`（角色定妆图 + 种子值）、`scenes.finalPrompt/imageUrl`、`props.finalPrompt/imageUrl`。
  - 分镜通过多对多表绑定资产，生成时后端把绑定资产图作为参考图注入（`backend/src/services/final-prompt.ts`、`generation.ts`）。
  - 「绑定哪些资产」本身就是用户可精修的对象，且可视化呈现「未生成 / 未绑定 / 已绑定」三态。

#### ② 长剧怎么组织

- 数据模型（`backend/src/db/schema.ts`）：
  - `dramas（totalEpisodes/genre/style/aspectRatio）`。
  - `episodes（episode_number, title, content, script_content, status, videoUrl, imageConfigId/videoConfigId/resolution）`——集级可独立配置出图/出视频模型。
  - `storyboards（episode_id, storyboard_number, scene_id）`。
  - **角色/场景/道具挂 `drama_id`，全剧共享**（跨集一致的基础），集级通过 `episode_characters / episode_scenes / episode_props` 关联表取用。
  - `sys_task` 统一任务表（L203）：type(image|video) + params(JSON) + resultUrl + status + errorMsg，一张表管所有生成任务。
  - `video_merges` 合成表。
  - **没有「季」概念**，两级（剧→集）足够支撑几百集。
- 导航：
  - `frontend/app/pages/index.vue`：项目卡片列表，只显示 counts（`characters.length/scenes.length/episodes.length`），**不加载全集数据**。
  - `frontend/app/views/drama/detail.vue`：集列表。
  - 每集一个 URL：`episode.vue?dramaId=&episodeNumber=`（`refresh()` 里 `drama.episodes.find(e => episodeNumber === ...)`）。
  - **每集独立页面 = 天然的路由级分页与懒加载**，单集内分镜只按 `episode_id` 查询。
- 性能要点：
  - 任务行 video `preload="none"`；缩略图 `loading="lazy"` + `thumbFallback`。
  - 任务列表按状态过滤 + 分页式渲染（一次只渲染本集）。
  - 没有任何一次性把全部集的分镜拉进内存的代码路径。

#### ③ 生成→人工审核→修改→重跑的循环

- 状态机：`storyboards.status`（pending/done/failed）+ `sys_task` 记录每次生成（含失败原因、错误码 `errorCode`）。
- 循环设计：
  1. AI 拆分镜（`doBreakdown` → storyboard-breaker skill）→ 落库为 pending。
  2. 用户在检查器**改字段**（blur 保存）→ 状态不变。
  3. 用户显式点「生成」`genVid(sb)` → sys_task 插入 processing → 前端轮询。
  4. 成功 → done，产物回写 storyboard 字段；失败 → failed，行内诊断 + 一键重试。
  5. 批量：`batchVideoPrompts`（进度 done/total）、`batchVideos`、选择模式（`videoSelectMode` + 「全选/选缺的/清除」快捷操作）。
- AI 对话改分镜：`backend/src/routes/agent.ts`（Mastra agent，`maxSteps: 20`，非流式 + toolCalls 收集）。
  - 工具（`backend/src/agents/tools/storyboard-tools.ts`）：`read_storyboard_context` / `save_storyboards` / `update_storyboard`。
  - **Agent 与手工编辑写同一个数据库**，改完前端刷新即可见——没有 diff 审批，信任模型 + 可重跑兜底。
  - script 工具同理（`script-tools.ts`：`read_episode_script / rewrite_to_screenplay / save_script`）。
- 分镜拆解质量规范：`backend/workspace/skills/storyboard-breaker/SKILL.md`。
  - 段落 8-15s、段内 2-4 子镜头（2-6s）、节拍边界强制切段、不跨场景。
  - 台词时长硬规则：段落时长 ≥ 段内台词字数 ÷ 4.5字/秒 + 2s，装不下必须拆到下一段。
  - `backend/workspace/skills/` 下还有 script-rewriter / extractor / prompt-generator 三个环节 skill。

### 2. Toonflow——「画布+文档双面板 + Agent 可编程控制」范本

#### ① 双面板分工

- 入口：`apps/web/src/pages/workspace/index.vue`。
- `activePanel: "canvas" | "document"` —— **二选一全屏切换**（el-segmented 切换器），不是左右拼接。
- 右侧 `floatingAgent.vue` 浮动对话栏，宽度可拖（`agentWidth`）。
- 切换面板前 `switchPanel()` 先 `flushSave()` 保证当前面板落盘；`onBeforeRouteLeave` 有未保存拦截。
- **画布面板**（`panels/canvas/`，基于 Vue Flow）：
  - 节点=文件：画布本身是 JSON 文件（`canvasFile.ts` 校验根对象首字段 `"toonflowCanvas": true`）。
  - 节点类型（`packages/nodes/`）：`textNode / imageNode / imageGenerationNode / videoGenerationNode / audioNode / audioGenerationNode / director3dNode / frameAnalysisNode`。
  - **编辑发生在节点内**：`imageGenerationNode/src/index.vue`（592 行）——
    - `promptInput`：提示词编辑，带参考提及（referenceMentions）、素材提及、模型选择，支持 **inpaint 模式**（`data.inpaintPrompt`，原图+区域引导图编号关系写进 prompt）。
    - `mediaHistory` 组件：**该节点的产物历史列表，点选历史即回填 `outputs.image`** ——版本对比与回滚的轻量实现。
    - `referenceItem` / `useNodeReferences`：参考图列表，节点间连线/提及互相引用（`referenceOrder` 记录每个输入槽的引用顺序）。
    - `useNodeGeneration` + `generationController.abort()` + `recover(recoveryData)`：**生成任务可中断/恢复**，失败不丢上下文。
  - 其余画布基建：`useCanvasHistory`（画布操作历史）、`nodeClipboard`、`canvasQueries`、`arrangeSelection/arrangeCanvas`（自动布局）、`nodeSearch`。
- **文档面板**（`panels/document/`）：
  - `fileTree.vue`：**虚拟化树**（`treeVirtualizer` + `visibleRows` 绝对定位 translateY），几百个文件也不卡。
  - `editorTab` 多标签编辑、`quickOpen` 快速打开、`workspaceSearch` 全文搜索。
  - 文本类精修（剧本/小说原文）在这里做。
- **Agent 控制协议**（关键）：
  - `index.vue` 里 `registerWorkspaceControl`（`@/lib/mcpControl`）暴露：`switchPanel / getDocument / openDocument / writeDocument` + 画布通用 call。
  - **Agent 可以自己切面板、读文档、写文档、操作画布节点**。
  - 用户在对话里 `@` 引用画布/节点/产物/资产（`apps/web/src/components/agent/mentionSources.ts`，canvases/nodes/outputs/assets 四类提及源）。
  - 分工不是「对话只读、面板可写」，而是「**对话与手工都能写，落点都是同一批文件**」。

#### ② 集/章节管理

- 没有 built-in 剧集模型——**文件系统即数据模型**：
  - 章节 = 文件夹，集 = 文档文件或画布文件。
  - 长篇支撑靠 `fileTree.vue` 虚拟化树 + 全文搜索 + quickOpen。
  - 节点产物存 `assets/<nodeId>/` 目录；删除节点时 `getCanvasAssetDirectories()`（canvasFile.ts）只清理无引用的资产目录，避免误删共享目录。
- 复制节点时 `remapNodeReferences()`（canvasFiles.ts）重映射引用 ID 并**清除供应商任务身份**（`delete node.data.mediaTask`）——复制体是新任务，不继承旧生成。

#### ③ Agent 怎么帮精修

- 对话改内容：Agent 通过 control 协议 `writeDocument` 写文档；写完自动切到文档面板让用户看结果。
- 手动精修：画布节点内字段编辑 + 产物历史回填 + inpaint 局部重绘。
- 产物级生成（贵）始终显式触发：节点上的生成按钮或对话里点名节点生成。
- 结论：**对话负责「批量与语义」，节点负责「单点精修与产物历史」**，两路写同一文件系统。

### 3. ArcReel——「文件账本 + 确认门 + 供应商素材库」工业范本

技术栈：Python 后端（`lib/` 领域层 + `server/` Nest-like 服务层）+ React 前端（`frontend/src/`）。

#### ① 小说→长剧改编流水线

- **分集账本**（`lib/episode/episode_ledger.py`）：
  - `project.json` 的 `episodes[]` 是分集**单一真相源**。
  - 条目字段：`episode / title / script_file / source_range / hook / outline / ledger_status(planned|consumed|stale)`。
  - 整本小说按 `source_range`（规范化文本的字符区间）切成 `source/episode_N.txt` **派生文件**。
  - 源文指纹存 `SOURCE_FINGERPRINTS`（路径 → 归一化文本 sha256），原文一变指纹失效 → 账本状态变 stale → 规划入口拒绝执行并指引全量重置（`episode_planner.py` / `episode_reset.py`）。
  - 跨集钩子：`hook` / `next_episode_teaser` 由分集账本派生，直接写进每集剧本（`script_models.py` 的 `NarrationEpisodeScript.hook`）。
- **分集体量**（`lib/episode/episode_layout.py`）：
  - 整本源文按集切成 `LayoutSegment` 只读投影（kind: episode|unsplit，start/end 偏移，units 阅读单位）。
  - 体量按 `source_language` 数阅读单位，朗读时长按项目语速折算（`lib/speech/speech_rate.py`）。
  - 相关模块族：`episode_planner / episode_replan / episode_manual_split / episode_target_duration / episode_target_volume / episode_trash`——分集本身就是可精修的对象（重切/手切/重规划/目标时长调整）。
- **剧本结构**（`lib/script/script_models.py`，Pydantic `extra="forbid"` 严格模式）：
  - `EpisodeScript → segments[]`，每个 segment：
    - `segment_id`：`E{集}S{序号}` 或 `E{集}S{序号}_{子序号}`。
    - `duration_seconds`（1-60）、`segment_break`（场景切换点）。
    - `novel_text`：**小说原文原样保留**（用于后期配音对齐）。
    - `characters_in_segment / scenes / props`：资产引用。
    - `image_prompt{scene, composition{shot_type, lighting, ambiance}}`。
    - `video_prompt{action, camera_motion, ambiance_audio, dialogue[]}`（DramaVideoPrompt/NarrationVideoPrompt 分方言）。
    - `generated_assets{storyboard_image, storyboard_last_image, grid_id, grid_cell_index, video_clip, video_uri, narration_audio, status: pending|storyboard_ready|completed}`。
    - `needs_replan`（需人工重新规划）、`pending_authoring`（待编写）。
  - **枚举漂移防御**：`ShotType` / `CameraMotion` 用 Literal 词表 + `_canon_enum_key` 机械归一（大小写/分隔符折叠）；词表外值降级为默认值（Medium Shot / Static）并 warn——不因单镜词汇漂移让整集生成失败。
- **章节→集→镜的拆解链**：原著分析 → 分集（账本）→ 每集 script_plan（结构化中间态）→ 确认晋升正式剧本 → 分镜图（含宫格模式 `lib/grid/`，一张图出多镜首帧摊薄成本）→ 视频。

#### ② 质量控制/一致性审计落地

- **script_plan 中间态确认门**（`lib/script/script_review.py`）：
  - AI 生成的结构化 `script_plan_normalized_script.json` 是**草稿**，用户（Web 结构化编辑器 / Agent 确认工具）确认后才「晋升」为正式脚本。
  - 确认状态**不存布尔值**：存「确认时的内容指纹」于 `project.json episodes[i].script_plan_review`，读时比对 live 指纹派生 confirmed/pending（「能算不存」约定）。
  - 因此：重跑 normalize、Agent 草稿晋升改写、Web 手改——任何一方动了内容，自动回到待确认，无需各写路径各自上报。
  - 写盘走 `script_plan_write_lock`（per-path 锁，挂在 ProjectManager.file_lock 下）+ 乐观并发比对；四条写路径（Web 保存/重拆分/晋升/迁移回写）汇入同一出口。
- **「不更坏」错误集 diff**：
  - Agent `patch_episode_script` 后跑 Pydantic 校验，before/after 的 errors 集合对比，新增错误即拒绝写入。
  - `extra="forbid"` 保证 typo/幻觉字段一定会成为新错误（否则会被静默丢弃、错误集 diff 失效）。
  - `draft_quarantine.py` / `draft_violation.py` 做草稿隔离与违规处理。
  - `script_structure_validator.py` 做结构校验；`script_batch_edit.py` 支持跨镜批量编辑。
- **供应商素材库（一致性的硬工程）**（`lib/asset_library/`）：
  - 角色/场景参考图一次性上传到供应商素材库（火山方舟 Ark 协议），此后生成用 **`asset://` 素材引用**代替每次重传图片。
  - `generation_inputs.py`：按「发出的字节对应的内容版本」查选定关联，可用即替换为 asset:// 引用；读侧（报价/预览）与执行侧按同一规则选择。
  - `links.py` 状态机：pending / submitting / processing / **active（唯一可用于生成）** / failed / uncertain。
  - `bindings.py`：推理凭证 ↔ 素材库范围的显式绑定，按云账号身份摘要（站点+AccessKeyID sha256）冻结——换 Key 即视为另一个资源域。
  - `VersionManager`（`lib/artifacts/version_manager.py`）管理内容版本：一致性以「内容版本 + 供应商素材 ID」对锚定。
  - **这是跨镜跨集角色一致性最硬的实现：一致性由供应商侧素材 ID 保证，不靠 prompt 重述。**
- **产物审计**：
  - `lib/video_review/contact_sheet.py`：为视频版本出联系表（contact sheet）供 Agent 看图审阅；`sampling.py` / `signals.py` 抽检与信号。
  - 前端 `frontend/src/components/workflow/WorkflowPanel.tsx`：问题清单（ProblemList）+ 过期产物（StaleArtifacts）+ 步骤准入（StepActButton），对应 `lib/workflow/workflow_rules.py`。
- **资产圣经页**（`frontend/src/components/canvas/lorebook/`）：
  - CharactersPage / ScenesPage / PropsPage；`CharacterDerivativesField` 角色派生图管理；`MergeAssetDialog` 合并重复资产；`useStaleRegenerateConfirm` 过期重生成确认。

#### ③ 长篇数据量下的性能方案

- 每集数据是独立 JSON 文件，页面按集路由：`frontend/src/components/canvas/episode-page/EpisodePage.tsx`（多视图 tab：原文视图 / 剧本 / 剪辑线，`episode-view.ts` 管视图状态）。
- 组件懒加载：`LazyBoundary`（EpisodePage.tsx 内 import）。
- 分镜产物引用按路径惰性读取；宫格生成摊薄请求量。
- 任务准入系统（`server/services/admission/`）控制并发。
- 前端 stores 按页面域拆分（cost-store / episode-surface-store / prompt-authoring-store），不全局塞数据。

### 4. LocalMiniDrama——列表+画布双视图同源同步

- 两个视图：
  - 列表视图 `frontweb/src/views/DramaDetail.vue`（1535 行）。
  - 画布视图 `frontweb/src/views/DramaCanvas.vue`（1159 行，Vue Flow）。
- **共享同一个 drama 对象**（Pinia `frontweb/src/stores/film.js` + API `refreshDrama`）。
- 同步机制（DramaCanvas.vue L396 `rebuildGraph()`）：

  ```js
  buildDramaCanvasGraph(drama, {
    episodeId, savedLayout, workflowGroups,

  })
  ```

  - **业务数据是唯一真相，画布节点是投影**。

## 二、必答四问

### A. 精修的最佳交互形态

行业标准是一个五步循环：**低密度浏览 → 大空间检查器 → 字段级编辑 → 单镜局部重跑 → 产物历史对比**。三家各给出一种成熟形态：

1. **列表 + 检查器（huobao）**：
   - 分镜列表行只放「缩略图 + 状态 + 时长」，点选后展开大检查器。
   - 所有字段就地编辑、blur 保存（`updateField` 单字段 PATCH）。
   - 编辑与重跑同处：改完 prompt，旁边就是生成按钮。
   - 适合逐镜过片式精修。
2. **全屏聚焦编辑器（ArcReel 每集全屏 page；YIMU 已有雏形）**：
   - ArcReel 每集一个全屏页面，多视图 tab（原文/剧本/剪辑线）。
   - 适合单镜深度精修：多字段 + 参考图管理 + 首尾帧并排对比。
3. **节点画布 + 产物历史（Toonflow）**：
   - 每镜/每资产是节点，节点内直接生成与编辑。
   - `mediaHistory` 保留每次产物历史，点选回填；inpaint 圈选局部重绘。
   - 适合视觉探索型精修。

**共性规范**（可作为 YIMU 精修交互的设计标准）：

- **改什么粒度**：字段级。结构化字段（景别/机位/运镜/时长/台词/提示词）分字段存，不存大文本块；blur 保存，无保存对话框。
- **怎么局部重跑**：单镜重跑带 `forceNew`；锁定字段（`shots.locked`）不重算；改描述不自动触发重跑，重跑永远显式。
- **怎么对比版本**：产物历史列表（每张图/段视频都是一次 asset 记录）+ 点选回填 + 并排对比（首帧/尾帧、剧本/分镜）。
- **失败处理**：行内诊断 + 一键重试 + 失败批量恢复 + 状态过滤。

### B. 长篇数百集的组织架构

- **数据模型**：
  - 层级：`项目 → 集 → 场 → 段 → 镜`（huobao 两级、ArcReel 五级；季都不需要）。
  - **资产挂「剧」，镜头引用靠绑定**：huobao `storyboard_characters/props` 多对多；ArcReel `characters_in_segment` + 供应商素材关联。
  - **集是调度与确认的原子单位**：ArcReel 确认指纹按集存（`episodes[i].script_plan_review`）；huobao 每集独立配置模型。
  - **跨集状态用账本行承载**：ArcReel `source_range / hook / ledger_status`；drama-skills `handoff_state / continuity_deltas`。
- **导航树**：
  - huobao：项目卡列表 → 集列表 → **每集独立 URL 页**（路由级分页）。
  - ArcReel：集列表 + 每集多视图 tab。
  - Toonflow：虚拟化文件树 + 全文搜索 + quickOpen。
  - 共识：**没有任何一家把几百集塞进一个右栏**。
- **性能方案**（按层次）：
  1. 路由级分页：每集一页/一 URL（huobao）。
  2. 数据按集查询；首页列表只带 counts，不加载全集（huobao index.vue）。
  3. 虚拟化列表：Toonflow `fileTree.vue` 的 treeVirtualizer。
  4. 懒加载组件边界：ArcReel `LazyBoundary`。
  5. 媒体懒加载：video `preload="none"` + poster、img `loading="lazy"` + fallback（huobao）。
  6. Agent/审查按 scope 按需读上下文，不预加载整个项目（drama-skills review rubric 机制）。
  7. 生成成本摊薄：宫格图一张出多镜首帧（ArcReel `lib/grid/`）。

### C. 一致性控制（工程层，不只 prompt）

五层机制，从软到硬，可叠加：

1. **绑定表（软）**：镜头 ↔ 资产多对多绑定，生成时注入参考图（huobao）。YIMU 已有 `shots.referenceImageUrls / characterIds` 字段，缺绑定管理 UI 与三态可视化（未绑定/未就绪/就绪）。
2. **锚点派生链（轻硬）**：角色一张正面全身锚点，所有视图/所有集只参考锚点；重出锚点自动标过期（shuohao character-refs）。YIMU `characters.identityKit`（portraitUrl + views + identityDescriptor，schema.ts L574）已有字段，缺「派生过期标记」与「views 只参考锚点」的生成约束。
3. **供应商素材库引用（硬）**：参考图上传一次得 `asset://` ID，按内容版本选用（ArcReel `lib/asset_library/`）。依赖 Ark 类供应商，可作可选增强。
4. **跨集状态账本（剧情一致性）**：每集 `handoff_state === 下集 incoming_state`、道具 `continuity_deltas` 状态机（drama-skills）；机械校验用脚本（shuohao 18 道质量门、ArcReel `script_structure_validator` + 枚举归一）。YIMU 已有 `shared/shot-continuity.ts`（轴线九宫格）与 `shared/qc-rules.ts`，可扩到集间。
5. **审查与确认分离（流程）**：
   - 独立 reviewer 角色 + `Blocker·REV-xxx` 报告格式，审查只指出问题不改文件（drama-skills review）。
   - 内容指纹确认门：内容一变自动回待确认（ArcReel `script_review.py`）。
   - 「不更坏」错误集 diff：AI patch 前后校验错误集合对比，变坏即拒（ArcReel）。

### D. 对话与面板的分工边界

| 修改类型 | 用对话 | 用面板 | 依据 |
|---|---|---|---|
| 语义级/跨文件批量（改人设并同步所有镜） | ✔ | ✘ | huobao agent tools；Toonflow writeDocument |
| 生成编排（拆分镜、批量出提示词、重试失败） | ✔ | ✔（批量按钮） | huobao batchVideoPrompts |
| 精确字段微调（改一句台词、换景别） | ✘ | ✔ | huobao updateField |
| 视觉选择（选参考图、选历史产物、inpaint） | ✘ | ✔ | Toonflow mediaHistory / referenceItem |
| 诊断（为什么失败、为什么过期） | ✔ | ✔ | huobao copyVideoDiagnostics；ArcReel StaleArtifacts |
| 剧本全文重写 | ✔ 产出草稿 | ✔ 审阅确认 | ArcReel script_plan；zenstory diff |

**边界规则**（四家共识）：

1. **同一数据源**：对话与面板写同一 API/文件（huobao agent 直接写 DB；Toonflow agent 写同一批文件；LocalMiniDrama 落库后 refresh 收敛）。不存在两套状态。
2. **产物级/全文级变更必须可审**：zenstory pendingEdits diff 审批，或 ArcReel 中间态 + 确认指纹。面板手工编辑即时生效（粒度小、可逆、用户亲手）。
3. **对话改意，面板落地**：对话说完改什么，落点在面板以草稿/diff 呈现，用户在面板确认后才触发昂贵的生成。ArcReel 的「script_plan 草稿 → 确认晋升 → 生成」是这一分工最完整的实现。
4. **Agent 可自跳转上下文**：Toonflow agent 可切面板/读文档；huobao agent 有 read_storyboard_context。对话不瞎改——先读后写。

3. **性能**（改动量：**小-中**）：
   - 分镜卡片列表与集列表引入虚拟化（`@tanstack/react-virtual`，学 Toonflow treeVirtualizer）。
   - 媒体预览保持 `MediaOrMissing / Lightbox` 懒加载；新增集列表分页或滚动加载。
   - 生成任务面板按 episode 分组显示进度（现有 `server/modules/queue/` + `generation_jobs` 表已有基础）。
   - 首页项目列表维持只带 counts 的现状。

### 方案三：一致性工程方案

1. **绑定管理 UI**（小）：方案一第 3 步的参考图绑定区即第一层（软一致性）。
2. **锚点派生链 + 过期标记**（中）：
   - `server/modules/bible/bible.service.ts` 已生成 identityKit（portraitUrl + views）。
   - 补两点：views 生成时强制只参考 portraitUrl 锚点（学 shuohao character-refs）；锚点重出时把引用它的 shots 置「过期需重生成」标记（shots.metadata 或新列），列表/精修器显示过期徽标。
3. **集间状态账本**（中）：
   - `episodes.metadata.handoff_state` 存简化三维（剧情要点/人物关系/关键道具状态）+ `continuity_deltas`。
   - 写集时后端校验「本集 incoming === 上集 handoff」，不一致进 QC 问题清单（`server/modules/qc/qc.service.ts` + `shared/qc-rules.ts` 扩展集间规则）。
4. **确认门**（中）：
   - AI 产出的剧本/分镜改动先落 `draft`（shots.status 已有 draft 态），面板 diff 确认后置 pending 生成。
   - 对话侧沿用/扩展现有 `GateCard`（`client/src/components/studio/chat/`）呈现确认卡片。
   - 「不更坏」校验放 `server/modules/qc/`：patch 前后各自跑 qc-rules，新增问题即拒绝写入。
5. **（可选，大）供应商素材库**：接入 Ark 素材库后参考图按 `asset://` 引用；镜像 ArcReel `lib/asset_library/links.py` 的 active/failed 状态机与内容版本绑定。

### 方案四：对话/面板分工规范（建议写入 AGENTS.md）

1. **同一数据源**：对话与面板共用同一 API，禁止前端另存副本（`useStudioData.ts` 已是单源，保持）。
2. **对话可做**：剧本/分镜语义修改、跨镜批量改写、生成编排、诊断问答；**产物级修改必须经确认**——Agent 写入保持 draft/GateCard 确认流。
3. **面板独占**：字段级精修（FocusEditor）、参考图/历史产物选择、单镜重跑按钮、锁定（`shots.locked`）。
4. **红线**：Agent 不直接改 `locked` 的镜；不越过确认门触发批量生成；先读（read_storyboard_context 式上下文工具）后写。
5. **可追溯**：每轮对话产出的结构化修改附 `reason` 字段落进 metadata，便于审查回溯（学 drama-skills 审查的「位置+证据+修订结果」引用格式）。

---

## 四、一页结论

- **精修** = 字段级结构化数据 + blur 保存 + 全屏聚焦编辑器 + 单镜局部重跑 + 产物历史对比（huobao / ArcReel / Toonflow 三家同构）。
- **长篇** = 集（episode）作为导航与确认原子单位；资产挂剧；账本管跨集状态；每集独立 URL + 虚拟化 + 按集查询。
- **一致性** = 绑定表（软）→ 锚点派生（轻硬）→ 供应商素材库（硬）→ 状态账本机械校验（剧情）→ 确认指纹门（流程），五层叠加。
- **分工** = 对话改意（diff/草稿待确认），面板落地（精修 + 选择 + 触发昂贵生成）；两边同一数据源。
